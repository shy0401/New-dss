# 공통 데이터 기준 (수집 · 계산 · 보고서)

> **자료를 모으기 전에 이 문서부터 읽습니다.** 팀원 누구나, 어느 지역이든, 사람이 하든 AI 도구로 하든 같은 기준으로 모으고 같은 공식으로 계산해야 결과를 합치고 비교할 수 있습니다. 이 문서가 그 기준의 **유일한 원본**입니다. 코드의 상수·규칙이 이 문서와 다르면 둘 중 하나가 틀린 것이니, 같은 커밋에서 함께 고칩니다(9절).

- 판: 1.63 (2026-11-25, 5.15 지역 감축 제안의 녹지 상쇄 입력 · 태양광 인증 · 사례 수준 · 추정 범위 · 조합 셋) · 근거: [팀 데이터 비교](TEAM_DATA_COMPARISON.md), [탄소 계산](CARBON_METHOD.md), [정확도 점검](ACCURACY.md), 팀 데이터셋 urban-carbon의 `config/rules.yaml`·ADR
- 점검 명령: `docker compose exec api python -m app.cli check-standard` (8절)

## 0. 작업 전 확인 (매번)

1. **범위를 한 줄로 적는다**: 지역(시·군·구 5자리 코드), 기간(YYYY-MM ~ YYYY-MM), 격자(500m), 자료 묶음. 예: `52110 전주시 · 2020-01~2025-12 · 500m · 건축HUB 전 지번`.
2. **이미 있는지 본다**: 앱 **수집 데이터 → 빠진 자료 전부 수집**의 표, 또는 `python -m app.cli status`. 있는 자료를 다시 받지 않는다(일일 한도를 아낀다).
3. **출처를 2절 표에서 고른다.** 표에 없는 출처는 먼저 공식 안내 주소·단위·기준 시점을 확인해 표에 한 줄 더한 뒤(9절) 받는다. 확인 못 한 것은 "확인 필요"라고 적고 짐작으로 채우지 않는다.
4. **키는 `.env`에만** 둔다. 화면·로그·문서·커밋·메신저에 키를 붙이지 않는다.
5. **받는 길은 이 저장소 수집기**(`scripts\dss.cmd Collect / CollectHistory / 지역 준비`)를 쓴다. 직접 받은 파일은 `data/raw/<출처>/`에 그대로 두고 앱의 파일 올리기나 가져오기 명령으로 넣는다.
6. **끝나면** `check-standard`를 돌리고(8절), 공유할 때는 `ExportBundle`, 받을 때는 `MergeBundle`을 쓴다(7절).

## 1. 원칙 여섯 가지

1. **없는 값은 0이 아니다.** 관측이 없으면 NULL(빈칸)로 두고 화면·보고서에 "자료 없음"으로 쓴다. 제공기관이 0을 준 경우만 0이다.
2. **원자료는 고치지 않는다.** 이상한 값은 상태(`quality_status`, 표시 열)로 표시만 하고, 계산에서 뺄지는 규칙(4절)으로 정한다.
3. **값의 종류를 섞지 않는다.** 관측 `OBSERVED` · 공공데이터로 계산 `CALCULATED` · 추정 `ESTIMATED` · 대체 자료 `FALLBACK` · 시나리오 `SCENARIO`를 구분해 저장하고 표시한다.
4. **단위는 이름에 붙인다.** `_kwh`, `_m2`, `_kgco2eq`, `_tco2e`, `_c`, `_persons`. CO2와 CO2eq를 섞지 않는다.
5. **계수·기준값·임계값은 한 곳에서.** 이 문서 5절의 표와 코드 상수(`emissions.py`, `kapt_energy.py`, `area.py`)가 같아야 한다.
6. **출처를 남긴다.** 원본 파일 경로 · 받은 날 · 기준 시점은 DB `raw_data_assets`에, 파일 내용의 SHA-256 · 크기는 받은 폴더의 MANIFEST에 기록한다(`raw_data_assets.id`는 경로로 만든 값이라 내용 해시가 아님 — 2026-11-22 근거 점검으로 문구를 실제에 맞춤). 보고서의 숫자는 이 기록까지 거슬러 갈 수 있어야 한다.

## 3. 지역·격자·시간 기준

| 항목 | 기준 |
|---|---|
| 지역 코드 | 법정 시·군·구 5자리(예: 전주 52110, 완산구 52111, 덕진구 52113), 법정동 10자리. 행정동 통계는 SGIS 코드로 따로 둔다. 2023-10 전북 코드 변경(45→52), 2026 인천 개편 구는 코드 대응표(`regions.py`)로 잇는다 |

| 월 | `use_ym` = `YYYYMM`(사용 연월). K-apt는 부과 연월을 그대로 쓴다 |
| 연간 값 | **12개월이 모두 관측된 지번(단지)만** 합한다. 11개월 이하인 지번은 그해 합계에서 빼고 "12개월 계측 지번 N곳"을 함께 적는다 |
| 기준 연도 | 화면 기본은 12개월이 다 모인 최근 연도(지금 2025) |

| 추정·대체 값 | 상태 열(`data_class`, `source_type`)을 반드시 함께 저장 | 배지 |

**하지 않는 것**: 관측 표의 빈 달을 앞뒤 달로 **채워 넣기**(빈 자리 추정은 4.1절 규칙으로 별도 표에만), 행정동 값을 격자에 면적으로 나누기, 다른 연도의 값을 그 해 값처럼 쓰기(쓸 때는 "2024년 값"처럼 연도를 적는다), 단위가 다른 두 출처를 더하기, 추정값을 관측 합계에 더하기.

### 4.1 빈 자리 추정 (추정 계층, `estimated_values`)

## 5. 계산 공식

기호: E = 에너지(kWh), C = 탄소(kgCO2eq), A = 연면적(m²), y = 연도, F_e(y) = 그해 전력 계수.

### 5.1 연간 에너지와 칸 집계
- 지번 연간: E_p(y) = Σ_(m=1..12) E_p(y,m), **12개월 모두 있을 때만**.
- 칸 연간: E_g(y) = Σ_(p ∈ 칸 g, 12개월 완비) E_p(y). 지번은 연속지적 필지 대표점이 들어간 칸에 넣는다(`parcel_grid`).
  연속지적도에 없는 계량 지번(나중에 분할·재번호된 땅)은 같은 법정동·본번 지번이 가장 많이 든 칸에 넣고(`MAIN_LOT_SIBLING`), 그런 지번도 없으면 건축HUB가 준 주소의 VWorld 좌표가 든 칸에 넣는다(`VWORLD_ROAD_ADDRESS`·`VWORLD_PARCEL_ADDRESS`). 값은 관측 그대로이고 위치만 이렇게 정한다. 셋 다 안 되면 칸에 넣지 않는다(0으로 채우지 않음).

### 5.2 원단위
- I = E / A (kWh/m²·년). A는 **같은 지번에 연결된 건축물대장 연면적의 합**. 연면적이 없는 지번은 분자·분모 모두에서 뺀다.

### 5.3 단위
- 1 tCO2e = 1,000 kgCO2eq, 1 MWh = 1,000 kWh, tCO2eq/MWh = kgCO2eq/kWh.
- 도시가스 부피 → 열량(필요할 때만): 1 Nm³ = 42.7 MJ(총발열량) = 11.86 kWh, 순발열량 38.5 MJ (에너지법 시행규칙 제5조 에너지열량 환산기준, 2022-11 개정).

### 5.4 전력 탄소
- C_e = E_e × F_e(y). **F_e(y) = 그해 12월 31일까지 공표된 가장 최근 GIR 승인 소비단 CO2eq 계수.** 같은 회차에 단년 값과 다년 평균이 함께 나오면 다년 평균을 쓴다.

| 계산 연도 | F_e (kgCO2eq/kWh) | 공표 | 근거 |
|---|---:|---|---|
| 2015~2018 | 없음 (NULL) | — | 이 도구에 원문 없음. 2차 출처(EG-TIPS 질의응답)에 "국가고유(11년) 0.4585"와 "0.4594(2011년 기준)"가 서로 다르게 적혀 있어 등록하지 않음(확인 필요) |
| 2019~2021 | 0.4594 | 2019-01-02 | 2018 승인 (CO2 0.4567 + CH4·N2O, SAR GWP) |
| 2022~2024 | 0.4781 | 2022-01-10 | 2021 승인 (수정본) |
| 2025 | **0.4330** | 2025-12-18 | 2025 승인, '21~'23 평균 소비단 (단년 2023 값 0.4173을 쓰면 3.6% 작음) |

### 5.5 가스 탄소 (국가 고유 계수, 2026-11-18)
- C_g = E_g × **0.1819** kgCO2eq/kWh. 만드는 법(순서대로, 코드 `backend/app/emissions.py`):
  1. CO2: 온실가스종합정보센터 **2021년 승인 국가 온실가스 배출계수(수정본)** 연료연소 1A, 도시가스(LNG) **15.236 tC/TJ** × 44/12 = 55,865.3 kgCO2/TJ(순발열량 기준). 2022~2025년 승인에서 바뀌지 않았다(원문 `data/raw/research/gir/b56_2_*`).
  2. CH4 · N2O: 고정연소의 국가 고유 계수가 없어(2021 승인의 국가 고유 CH4 · N2O는 도로수송뿐) IPCC 2006 지침 2권 2장 표 2.4 · 2.5(상업 · 주거) 천연가스 기본값 CH4 5 · N2O 0.1 kg/TJ.
  3. GWP: AR5(CH4 28 · N2O 265). GIR 2025 승인 전력 CO2eq 0.4330(= CO2 0.4307 + CH4 0.0057 · N2O 0.0082 kg/MWh)도 같은 GWP로 합산된다.
  4. 합계 56,031.8 kgCO2eq/TJ = **0.20171** kgCO2eq/kWh(순발열량 기준 kWh).
  5. 건축HUB 가스 kWh는 에너지 사용량이므로 총발열량 기준으로 본다(정부 별표 '연료별 국가 고유 발열량 및 배출계수' 각주: "온실가스 배출량 산정 시 순발열량을 사용하며, 에너지사용량을 집계할 경우 총발열량을 사용한다"; 도시가스 요금도 2012-07부터 열량(MJ) 기준). 에너지법 시행규칙 에너지열량환산기준(2022-11) 도시가스(LNG) 순 38.5 / 총 42.7 MJ/Nm³로 맞춰 0.20171 × 38.5/42.7 = **0.1819**.
- 건축HUB 문서에는 kWh 환산의 열량 기준이 따로 적혀 있지 않다. 순발열량 기준이 확인되면 5단계를 빼고 0.2017(+10.9%)을 쓴다(제공기관 확인 권장, 보고서의 민감도에 적는다).
- 예전 규칙(2026-11-18 이전): IPCC 기본 CO2 56,100 kg/TJ로 만든 0.1826(가정). 새 계수는 0.4% 작다.

### 5.6 여러 해 비교용 고정 계수
- 개발 전후·추이처럼 **사용량 변화만** 보려는 비교는 모든 연도에 같은 계수(최신 F_e, 지금 0.4330)를 쓴다. 연도별 계수를 쓴 대시보드 값과 다를 수 있음을 함께 적는다.

### 5.7 같은 지번 비교 (두 해)
- 두 해 모두 12개월 계측된 지번 집합 S: Δ% = (Σ_S E(to) − Σ_S E(from)) / Σ_S E(from) × 100.
- 한 해에만 계측된 지번은 곳 수와 kWh를 따로 적는다(합에 섞지 않음). 결측·비교 제외 연도(2020)는 from으로 쓰지 않는다.

### 5.8 개발 전후
- 사용승인 연도 t의 개발: 전 = t−w … t−1, 후 = t+1 … t+w 중 12개월 완비 연도의 평균(w = 2 또는 3). 변화율 = (후 − 전) / 전 × 100.
- 신축 몫 = 새 단지 연평균 / 후 기간 지역 연평균 × 100.
- 관측이 부족하면 추정: 늘어난 연면적 × 지역 관측 원단위, `ESTIMATED`로 표시.
- 팀 변화 모델(urban-carbon 7차)은 500m 칸 하나(또는 맞닿은 칸 묶음)의 **탄소공간지도 건물 배출 변화**를 따로 추정한다(`SCENARIO`). 위 관측 원단위 계산과 더하거나 평균하지 않고 나란히 보인다. 1,000 tCO2e 미만은 방향만 적고, 값을 쓸 때는 80% 구간(q10~q90)과 모델 이름·학습 합본을 함께 적는다. 입력 중 난방 · 가스 비중은 그 칸 자신의 값, 기상은 같은 시 관측소 값만 쓰고 없으면 NULL로 둔다(2026-11-17, [팀 데이터셋 7.3절](TEAM_DATASET.md#73-팀-변화-모델)). 빌려 온 이웃 값을 입력으로 쓰지 않는다. 팀의 추정 입력은 표에 공식 값이 있으면 그것으로 바꾼다: 총 연면적 추정 · 면적 비율 단지 세대수는 빼고(대장 연면적 · 세대수가 남음), 인구는 공개 칸 합과 비공개 칸 수, 건물 수는 제공값 합(없으면 NULL)으로 쓴다. 공식 값을 먼저 쓰고, 공식 값이 없는 곳만 추론으로 보탠다.
- 팀 변화 모델의 정답(탄소공간지도 500m 전기)은 한 배출계수로 맞춘다(2026-11-18). 받은 500m 전기는 2013~2022년이 0.4173, 2023년이 0.4781이고, 2024년은 인천 · 경기 25곳이 0.4781, 나머지가 0.4173이다(같은 칸의 해마다 비와 건축HUB 단지 칸으로 판정, 원주는 불분명이라 그대로). 0.4781인 2024년 전기에 0.4173 / 0.4781을 곱하고 건물 합계를 다시 계산한다(`deploy/team-model/elec_factor_2024.csv`). 받은 파일은 고치지 않는다. 이렇게 하지 않으면 2024년으로 끝나는 변화에 칸 전기의 14.6%가 개발과 상관없이 들어간다. 이 계산 정답은 `CALCULATED`이고 관측값과 섞지 않는다.
- 팀 변화 모델의 학습 행(2026-11-19): 지역 합계 급감 표시(`suspect_region_drop`)는 칸 단위로 다시 판정한다. 팀 규칙과 같은 해를 같은 기준(앞선 해 중앙값의 0.8배 이하, 1,000 tCO2e 이상 감소, 앞선 해 2개 이상, `rules.yaml` `emission_region_drop`)으로 찾고, 계수 맞춘 전기로 본다. 그 칸의 그해 값이 있고 자기 앞선 해(2개 이상) 중앙값의 0.8배 이상이면 표시하지 않는다. 이렇게 되살린 행은 학습 쌍에만 넣고 개발 사례(가중)로는 쓰지 않는다. 다른 제외 사유는 그대로다. 받은 표는 고치지 않는다(`deploy/team-model/region_drop.py`).
- 팀 변화 모델의 입력에서 후 해(`after_year`)를 뺀다(2026-11-19). 학습에 없는 미래 해는 마지막 해(2024)처럼 다뤄져 그해의 자료 특성이 계획 예측에 실리기 때문이다. 간격(몇 년 뒤)은 입력으로 남기고, 계획에 없으면 7년으로 둔다.

### 5.9 감축 노력 (목표 역산)
- 기준: 기준 연도 b의 관측 E_b, 원단위 I_b (공동주택 = K-apt, 건물 전체 = 건축HUB 계측 지번). 기준을 반드시 함께 적는다.
- 계획 반영(BAU): E_bau = E_b + I_b × (추가 연면적 − 철거 연면적), C_bau = E_bau × F.
- 목표: C_target = E_b × F × (1 − 목표%/100). 필요 감축 ΔC = C_bau − C_target (≤ 0이면 목표 충족).
- 선택지: 신축만 효율화 ΔC / C_new × 100, 전체 효율화 ΔC / C_bau × 100, 재생에너지 상쇄 ΔC / F (kWh/년), 태양광 ΔC / F / 발전량(kWh/kW·년).
- **목표 기준 둘(2026-11-23)**: 위 목표(구역 전체, 기존 건물 포함)와 함께 '개발 증가분 상쇄'를 따로 계산해 나란히 적는다. 증가분 ΔC_add = I_b × (추가 연면적 − 철거 연면적) × F(목표 %와 무관, 목표 0%일 때의 ΔC와 같음). ΔC = ΔC_add + E_b × F × 목표%/100(늘어난 몫 + 기존 건물 몫). ΔC_add ≤ 0이면 '늘지 않음'으로 적고 필요 감축량은 비운다(음수 · 0으로 쓰지 않음). 두 값은 같은 기준 건물 · 기준 연도 · 계수의 시나리오 값이고 서로 더하지 않는다. 팀 변화 모델의 예측(5.8)과도 더하거나 평균하지 않는다.
- **용도별 원단위(2026-11-23)**: 계획에 용도 줄(신축 · 철거)이 있으면 줄마다 E = 용도 원단위 × 그 줄 연면적으로 더한다. 상업(제1 · 2종 근린생활시설) · 업무 · 대형 판매 · 교육(교육연구시설) · 의료·복지(의료 · 노유자시설)는 건축HUB 12개월 계측 지번 중 주건축물 주용도가 하나인 지번의 Σ 전력 ÷ Σ 대장 연면적(5.2, 2~1,500 kWh/m²만)을 쓴다: 그 지역 지번이 **30곳** 이상이면 지역 값, 아니면 분석 지역(READY) 전체 값(근거표 `backend/reference/use_intensity_2025.csv`, `scripts/build_use_intensity.py`). 주거 · 오피스텔(대장 업무시설이지만 주거로 씀) · 지식산업센터 · 공업(지번 적음) · 기타는 지금처럼 고른 기준 건물의 구역 원단위. 용도 줄이 없으면 연면적 전체에 구역 원단위(이전과 같음). 탄소공간지도 기준(kcsm)에는 섞지 않음. 근거: 같은 자료에서 공동주택 38.6 대 근린생활 109.3 · 판매 122.9 · 업무 77.6 kWh/m²(2025, [점검 기록](records/2026-11-23-intensity-method-review.md))

### 5.10 기상
- 난방도일 HDD = Σ_일 max(18 − T_일평균, 0), 냉방도일 CDD = Σ_일 max(T_일평균 − **24**, 0) (°C·일, 한국가스공사 냉난방도일 통계 기준). 그달 일평균이 하루라도 비면 그달 도일은 NULL.
- 다시 계산(`apply-standard`)은 **도일 규칙(기준온도 · 빠진 날 규칙, `degree_days.RULE`)이 바뀌었을 때만** 한다. 기준 판이 다른 까닭(K-apt 규칙 등)으로 바뀌면 도일은 다시 계산하지 않고 저장값을 둔다(마지막에 적용한 규칙은 `data/ops/standard.json`의 `rule`). 다시 계산은 달마다 **그 값의 원본**으로 한다: 지역 기상의 ASOS 달(`OFFICIAL`, `KMA ASOS <지점> <이름>`)은 그 지점의 일자료 원본(`data/raw/kma/asos-regions/<지점>/`), 대체 달(`FALLBACK`)은 ERA5-Land 원본(`data/raw/weather-regions/<코드>.json`), 전주 ASOS 달은 저장된 일자료. 원본이 없거나 그달이 다 차지 않으면 HDD · CDD를 **둘 다 NULL**로 두고 센다(옛 규칙 값을 새 규칙 값처럼 남기지 않고, ERA5 값으로 덮지도 않음).
- 점검(`check-standard`): 지역 기상 ASOS 달의 도일이 그 지점 일자료로 다시 낸 값과 같은지 센다(다르면 FAIL, 일자료 원본이 없는 달은 따로 셈)

### 5.11 모델 검증
- 공간 교차검증(2km 블록), 같은 칸의 다른 연도를 학습·검증에 나눠 넣지 않는다. 오차는 nMAE와 R²를 함께, 표본 수와 함께 적는다.
- 팀 변화 모델의 점수는 팀 정의를 그대로 쓴다: 사례별 오차 = |예측 − 실제| ÷ |실제|의 중앙값(실제 100 tCO2e 이상 사례), ±50% 안 비율, 방향 일치, 예측 합 ÷ 실제 합. 학습 지역 사례는 그 칸을 빼고 학습한 교차검증 예측, 시험 지역 사례는 학습에 없던 지역에 고정 모델을 적용한 예측만 점수로 쓴다.
- 팀 변화 모델의 쓰임 단위는 **개발**(맞닿은 개발 칸 묶음)이다(2026-11-19). 성능은 개발마다 전 해 하나 · 후 해 하나로 그 칸들의 예측과 정답을 더해 잰다: 후 해는 두 해 모두 쓸 수 있는 칸이 늘어난 대장 연면적의 80% 이상인 가장 늦은 해, 채점은 그 칸들. 지역을 통째로 빼는 교차검증과 시험 지역을 함께, 범위 안 용도(주거 · 복합 · 상업)와 실제 1,000 tCO2e 이상으로 적고, 크기(1 · 2~9 · 10칸 이상)와 용도별 값을 같이 적는다. 예측 범위(q10~q90)는 이 개발 단위 잔차로 만든다([팀 데이터셋 7.3절](TEAM_DATASET.md#73-팀-변화-모델)).
- 여러 칸 개발(구역)은 용도별 합계를 쓸 수 있는 칸에 같게 나눠 칸마다 예측하고 더한다. 모든 칸은 같은 기준 해(칸 절반 이상이 쓸 수 있는 해 중 가장 늦은 해, 없으면 칸이 가장 많은 해)에서 시작한다. 쓸 수 있는 해가 없는 칸 중 모든 해에 배출이 없고 대장 연면적이 제공값 0이며 국토통계 건물이 없는 칸은 빈 땅(배출 0)으로 시작하고 추정으로 표시한다(대장 연면적이 NULL이면 빈 땅으로 보지 않는다). 그 밖의 칸은 빼고 이유를 적는다. 칸 수는 평가한 가장 큰 개발(64칸)까지. 사례 가중은 평가와 같은 `developments.csv` 사례로 한다.

### 5.12 다른 출처와 맞대기
- 탄소공간지도(모든 건물·tCO2e)와 이 도구(건축HUB 계측 지번·kgCO2eq)는 범위가 달라 **더하지 않고**, 같은 칸끼리 로그 값·순위로 비교한다.
- 선도소프트 100m(전기)는 지역 시뮬레이션에서 ① 구역 경계 안 100m 칸 합(경계 기준)과 ② 구역 500m 격자 안 100m 칸 합(이 도구와 같은 범위)을 따로 내고, ②와 같은 격자의 건축HUB 계측 전력 × 그해 F_e를 비율로만 맞댄다. 감축 노력의 '탄소공간지도 기준'은 ①·②의 제공 값(tCO2eq)을 그해 F_e(2023·2024 = 0.4781)로 전력량으로 되돌리고(제공기관이 계수를 밝히지 않아 **추정**: 2024년 전주 합계 = 한전 주택·일반·교육용 판매량 × 0.4781의 101.2%, 공공 500m 탄소공간지도와 모든 칸·달에서 0.4781/0.4173 = 1.1457배), 기준 = ①의 전력, 신축 원단위 = ②의 전력 ÷ 같은 격자의 건축물대장 연면적(그해까지 사용승인)으로 다른 기준과 같은 화면 계수를 곱한다. 총량은 한전 시군구 전력·지역 인벤토리와 맞댄다([팀 데이터 비교](TEAM_DATA_COMPARISON.md) 2절).

### 5.13 태양광 연 발전량 (추정)
- 1 kW 설비의 연 발전량(kWh/kW·년) = 그 지역 **수평면 일사량**(kWh/m²·년) × **성능비 0.80**. 1 kWh = 3.6 MJ, 설비 1 kW = 1 kW/m²(표준 조건) 기준이다.
- 일사량: 전주는 기상청 ASOS 146 일 합계 일사량(한 해 모든 날이 있을 때), 그 밖과 ASOS가 빈 해는 ERA5 일 일사량(0.25° 재분석, `FALLBACK`). 같은 해면 관측을 쓰고, 분석 마지막 연도 이하에서 가장 최근의 완비 연도를 쓴다.
- 경사 보정을 하지 않는다(경사면은 더 받으므로 필요한 설비 용량이 크게 나오는 쪽). 그늘·방위·설치 면적은 넣지 않는다.
- 사용자가 발전량을 넣으면 그 값을 쓰고 "사용자 입력"으로 적는다. 추정값은 보고서에 **"(추정값)"** 과 연도·일사량·성능비를 함께 적는다. 완비 연도가 없으면 설비 용량은 비운다(0 아님).
- 코드: `backend/app/solar.py` (`PERFORMANCE_RATIO`), 일사량 받기: `python -m app.cli backfill-solar [--region 코드,코드]`.

### 5.14 업계·정부 기준과 맞대기 (참고)
- 1차에너지 환산계수: 전력 2.75, 연료(가스) 1.1, 지역난방 0.728, 지역냉방 0.937 (한국에너지공단 제로에너지건축물 통합 인증시스템). 단위면적당 1차에너지 = 전력 kWh/m² × 2.75 + 가스 kWh/m² × 1.1 (건축HUB에 지역난방 열은 없음).
- 건축물 에너지효율등급 구간(주거용 1+++ 60 미만 … 7등급 370~420, 주거용 외 1+++ 80 미만 … 7등급 610~700 kWh/m²·년)과 제로에너지건축물 등급(에너지자립률 5등급 20% … 1등급 100%)은 **표준 조건의 설계 평가**(난방·냉방·급탕·조명·환기)라, 계량된 실사용 값을 그 위에 놓을 때는 "참고 위치"로만 쓰고 등급 판정이라고 쓰지 않는다.
- 신축 에너지자립률(참고) = 태양광 연 발전량 ÷ 신축 전력 부하 × 100 (둘 다 전력이라 1차에너지 계수가 같아 약분). 추가 연면적이 1,000m² 이상이면 의무 대상 규모일 수 있다고 함께 적는다: 공동주택은 주택건설사업계획 승인 대상(30세대 이상, 일부 단지형 연립·다세대 50세대)이 2025-06-30 이후 승인 신청분부터 1차에너지소요량 100 kWh/m²·년 미만 또는 사양 기준(국토교통부고시 제2025-313호 제7조, 주택법 시행령 제27조), 그 밖의 민간 건축물은 연면적 1,000m² 이상 ZEB 5등급 수준(한국에너지공단 안내, 법령 원문 대조 안 함). 세대수·용도·승인 신청 시점은 확인 필요.
- 국토교통부 2024 표준지표(중앙값, kWh/m²·년): 공동주택 중부 136·남부 111, 업무시설 중부 159·남부 102. 1차/최종 구분은 확인 필요.
- 표준지표 지역: 시군구 → 설계기준 지역 구분(국토교통부고시 제2026-360호 별표 1 비고, `backend/reference/design_zone_sigungu.csv`)에서 중부1·중부2 → 중부, 남부 → 남부. 제주는 표준지표 지역 값이 없어 맞대지 않는다(확인 필요). 표에 없는 코드도 맞대지 않는다(짐작하지 않음).

### 5.15 탄소 감축 방안 (실측 지표와 가정)
다른 안과 견주지 않고, 같은 계획을 '대책 없음'에서 시작해 수단을 차례로 더한 순서로 쓴다. 값이 없으면 그 단계를 빼고 0으로 채우지 않는다. 절감률은 설계 목표가 아니라 **실측에서 나온 지표**를 쓰고, 근거와 범위는 [감축 지표와 근거](REDUCTION_INDICATORS.md)에 둔다.
- **3D 계획안(검토 보고서 5절)**: 0) 대책 없음 = 기준안(같은 연면적, 관측 원단위 그대로) → 1) 단열·창호 기준 강화: 가스 사용 **13.7%** 절감(2026-11-20 다시 계산: 같은 시군구·세대수 구간에서 준공 시기만 다른 개별난방 단지 117쌍, 관리비 부과 면적당 = 같은 난방 면적 기준 짝별 중앙값, 95% 구간 **9.8~17.3%**. 연면적당 −33.9%는 새 단지 연면적의 난방하지 않는 면적 때문에 외피 효과로는 과대라 쓰지 않음. 같은 비교에서 세대 전기는 방향이 분명하지 않아 전기 절감은 넣지 않음. 이전 값 23.6%는 재현되지 않음) → 2) 지붕 태양광: 옥상 = 건축면적 합계 × **0.60**, 용량 = 옥상 ÷ **10 m²/kW**, 발전량 = 용량 × 5.13 발전량(자체 소비를 넘는 발전은 감축에 넣지 않음) → 3) 녹지·조경 흡수(상쇄): 녹지 면적(대지면적 × 녹지 비율) × 연 **1.0 kgCO2/m²**(= 10 t/ha. 국립산림과학원 표준 탄소흡수량 20년생 주요 수종 8.8~15.9 t/ha·년의 낮은 쪽, 가정. 국내 조경 식재지 실측 식재 면적당 0.38~2.37 kgCO2/m²·년 범위 안이며, 부지 전체 면적당 값과는 견주지 않는다. 새로 심은 나무는 처음 10년쯤 더 작다). 남는 전력은 운영 넷제로까지 필요한 외부 재생에너지(태양광 kW 상당)로 적는다. 에너지자립률 = 태양광 × 2.75 ÷ (절감 뒤 전력 × 2.75 + 가스 × 1.1), ZEB 등급(20·40·60·80·100%)은 참고 구간이다. 에너지 절약 운영(계량·제어·행동, 전력 4.8%, 원문과 맞는 2건 4.5~5.08%)은 입주 뒤 행동이라 2026-11-20부터 사다리에 넣지 않는다(계획 단계 밖, 지표만).
- **지표 범위 표시**: 계산은 중앙값(13.7%)으로 하고, 보고서에는 지표의 실측 범위(단열·창호 9.8~17.3%)와 그 범위에서 그 단계 감축량이 움직이는 폭을 함께 적는다(`ENVELOPE_GAS_SAVING_RANGE`, 단계별 `range_pct`·`reduction_range_kg`). 범위는 다른 단계를 그대로 둔 값이며 합계의 신뢰구간이 아니다.
- **지역난방 대상지(2026-11-20)**: 지역난방 열의 탄소는 배출계수가 없어 계산 밖이다(지역난방 단지의 건축HUB 가스 원단위 중앙값 3.3 대 개별난방 71.1 kWh/m², 단지 분석). 숫자는 바꾸지 않고, 대상지 격자에서 난방 방식을 아는 K-apt 단지의 지역난방 연면적 비중이 0보다 크면 계획안 · 검토 보고서 가정에 "그만큼 운영탄소가 작게 잡힘 · 단열·창호 근거는 개별난방"을 적는다(`service.heating_share` · `district_heating_note`). 열 계수가 있는 지역(한난 지사: 세종 · 수원 · 대구 달서 · 양산, 대체 계수: 강동 · 부산 강서 · 익산 · 남양주)은 5.16대로 "지역난방 열(추정)"을 따로 계산하고 문장도 그 계산 문장으로 바뀜
- **기준 연도(2026-11-20)**: 기준안은 보고서 연도의 관측 원단위로 만들고, 감축량은 그해 기준안에 대한 값이라 보고서 가정에 기준 연도를 함께 적는다(`building_plan(base_year=…)`, AGENTS.md "감축량에는 기준과 기준 연도"). 날씨를 맞춘 사용량도 해마다 달라 다른 해 기준안이면 감축량이 달라진다.
- 난방·급탕 전기화(히트펌프)는 초기 비용이 크고 국내 공동주택 실측 근거가 부족해(실측 1건) 기본 단계에 넣지 않는다(2026-11-11).
- **지역 시뮬레이션(구체적 감축 방안, 자동)**: 목표 기준 둘(5.9)마다 따로 낸다. 태양광은 **계획 건물 지붕 한도까지만** 채운다: 한도 = 계획 건축면적 합(동 수 × 동당 건축면적, 또는 연면적 ÷ 층수) × **0.60** ÷ **10 m²/kW**(3D 계획안 2단계와 같은 값), 태양광 = min(필요 용량의 10 kW 단위 올림, 한도). 한도를 넘는 몫은 태양광으로 세지 않고 **남는 양**(kgCO2eq · kWh · 구역 밖 태양광 kW 상당)으로 따로 적는다. 다 채우면 남는 양은 비우고 여유를 적는다(음수 · 0으로 채우지 않음). 건축면적을 모르면 연면적 × 0.60을 지붕의 위 한계로만 쓰고, 그 안이면 '확정 아님', 넘으면 남는 양을 '적어도'로 적는다(2026-11-23). 2026-11-20부터 신축 전력 11.3%와 기존 건물 운영 4.8% 절감을 넣지 않는다: 신축 통합의 원문과 맞는 근거(준공 시기 비교 국내 2곳, 총 최종에너지 −5.9~−12.1%)는 열 + 전기 값이고 전력 절감 근거가 없으며(이 도구 실측도 전기 차이 확인 못 함), 운영은 입주 뒤 행동이다. 발전량 근거가 없으면 상쇄할 kWh만 적는다. 추천 줄마다 그 조건에서 쓸 수 있는 수단(수단 목록 · 근거표)과 근거 종류를 붙이되, 감축 값이 있는 것은 이 계산이 낸 태양광 줄뿐이고 나머지는 지표만이다(값 비움). 녹지는 계획에 녹지 면적을 넣을 때만 따로 상쇄(kgCO2) 칸에 값이 있다(2026-11-25). 사용자가 넣은 조합(`mix`)과 따로 보여 준다.
- 지표는 사업·건물마다 달라질 수 있는 중앙값이다. 실측 근거가 없는 수단(단열 단독, 구조 방식, 저탄소 콘크리트)은 계산값·발표값만 있어 사다리의 지표로 쓰지 않는다.
- **수단별 따로 본 값(2026-11-16)**: 사다리에 넣지 않은 수단까지 한 목록(`backend/app/reduction_measures.py` `MEASURES`, 14개)으로 두고, 수단마다 대책 없음에 그 수단 하나만 적용한 연 감축량을 사다리와 따로 계산한다(`measures`). **서로 더하지 않는다.** 값을 내는 수단은 실측·기관 실적 근거가 있고 계획안의 전력·가스에 곱할 수 있으며 계획 단계에서 정하는 것뿐이고, 2026-11-20부터 사다리 밖에는 그런 수단이 없다(사다리 단계의 수단만 값이 있음). 세대 에너지 표시장치·스마트미터(전력 −11.7%, −15.9~−7.5%)는 설비 사양이고 효과가 입주 뒤 행동을 거치며 근거가 대조군 없는 설치 전후 1건(2010년 64가구 · 겨울 2개월)이라 2026-11-20부터 지표만이다. 신축 통합 기준(총 최종에너지 −11.4%, −12.1~−5.9%, 준공 시기 비교)과 에너지 절약 운영(전력 −4.8%, 입주 뒤 행동)은 2026-11-20부터 값을 내지 않는 지표만이다. 열회수 환기 총에너지 3.5%(1~6%)는 원문이 실측이 아니라 ECO2 계산값이라(2026-11-20 원문 대조) 값을 내지 않는다. 곱할 양이 계획안에 없거나 근거가 계산값인 수단(패시브 수준 외피, 창호 교체, 외부 차양, 열회수 환기, 공용부 조명, 승강기 회생제동, 콘덴싱 보일러, 지역난방 난방 제어)은 지표·근거·비용만 적고 값은 비워 둔다(0이 아님).
- **시공 단계 내재탄소(참고 계산, 2026-11-16)**: 지상 연면적 × **445.4 kgCO2/m²**(범위 **340.3~586.0**, 국내 27개 단지 282동 자재 생산 단계 평균, 산업연관분석). 시공·운송·해체, 지하주차장·부대시설 제외. 한 번 배출되는 양이라 연간 운영탄소 사다리와 합하지 않고 '대책 없는 연간 운영탄소의 몇 년치'로만 견준다. 자재·공법 수단은 모두 설계·계산 값이다: 저탄소 콘크리트는 레미콘 몫 **14.9%**에 **12.05%**(7.8~16.3%), 모듈러는 생산 단계 **35.1%**(35.1~37%, **13층** 이하 계획안에만), 구조 방식 전환·골조를 남기는 리모델링은 지표만(`EMBODIED_*`, `EMBODIED_MEASURES`, `MODULAR_MAX_FLOORS`).
- **지역 감축 제안의 녹지(2026-11-25, 계획 v3 D)**: 계획 입력에 녹지(식재) 면적 `green_area_m2`(0~10 km²)를 넣으면 녹지 줄이 `value_status` OFFSET, 상쇄 칸 `offset_kgco2` = 면적 × 연 1.0 kgCO2/m²(3D와 같은 상수, 범위 숲 기준 8.8~15.9 t/ha). 줄이는 것이 아니라 메우는 값이라 목표 · 추천 방안 · 남는 양 · 사용자 조합 어디에도 더하지 않음. 넣지 않으면 지금과 같음. 상수 1.0은 같은 분모(식재 · 수관 면적당) 국내 실측 0.38~2.37 kgCO2/m² 안이라 유지(L-049 단지 실측은 탄소 기준: 수관 면적당 0.5 kgC = 1.83 kgCO2, 우리 환산)
- **지역 감축 제안의 태양광 세 수준(2026-11-25, 계획 v3 E)**: 지붕 태양광 줄에 `pv_levels` — 인증 수준 = 계획 세대 수 × **0.20~0.61 kW/세대**(공식 자료: 한국부동산원 ZEB 인증사례집 2024 주거 사례 계산, LH 인천검단 AA10-2 0.383), 실제 사례 수준 = 세대 수 × **0.13~0.64 kW/세대**(기사: 올림픽파크포레온 0.128, 힐스테이트 검단 웰카운티 옥상 0.639, 공식 자료 교차 확인 안 됨) → 지역 발전량 × 전력 계수. 둘 다 지붕 한도로 자르고 `data_class` ESTIMATED. 지붕 최대(지금 값) · 목표 · 추천 방안에 더하지 않음. 세대 수(계획 주거 줄의 `dwellings` 합)가 없으면 이유만. 서울 · 제주는 녹색건축물 설계기준의 신재생 의무 비율(서울 고시 제2023-555호 9.5~10.5%, 제주 고시 제2025-160호 8~12%)을 지표 문장으로(값에 안 씀). 서울 환경영향평가 태양광 의무(2021-294호)는 2022-332호에서 빠져 쓰지 않음
- **지역 감축 제안의 추정 범위(2026-11-25, 계획 v3 F)**: 근거표 행의 값을 계획안의 값(감축 값 · 목표 · 추천 방안)에는 곱하지 않고, 원문 대조된 구간만 **추정 범위**(`data_class` ESTIMATED)로 따로 낸다. 한 줄마다 근거 · 곱한 양과 출처(`chain`) · 결과 kgCO2eq 범위 · 성립 조건. 어떤 합계에도 넣지 않음. ① 단열·창호(가스): 신축 주거 연면적 × 구역 가스 원단위(건축HUB 가장 최근 완전한 해) × 도시가스 계수 × 9.8~17.3%(이 도구 117쌍 짝 비교) ② 승강기 회생제동: 세대 수 ÷ 승강기 1대당 21.2~57세대(K-apt 2015년 이후 준공 5,763단지 10~90% 구간) × 대당 0.39~0.57 tCO2 ③ 옥상녹화(설계 지역 중부2만, 층수가 있을 때): 최상층 몫(1 ÷ 층수) × 냉방 2.35~3.97% · 난방 6.81~9.42%(김지현 외 2016, 서울 기상 계산). 쿨루프 · 콘덴싱 보일러 · 공용 조명 · 외부 차양은 지표(근거 부족 · 이미 의무 · 곱할 양 없음). K-apt `elect`는 전기 사용금액(원)이라 `elect − helect`로 공용 전기를 구하지 않음
- **지역 감축 제안의 조합 셋(2026-11-25, 계획 v3 I)**: 개발 증가분 기준(전력 운영탄소)에 A 지붕 최대(값, 추천 방안의 판정 · 남는 양 그대로 — 위 한계 · 지붕 없음 · 발전량 없음이면 값 없이 이유) · B 인증 수준 · C 실제 사례 수준(추정 범위). 칸을 나눠 냄: 태양광 뒤 남는 양(`after_pv`, A는 SCENARIO · B/C는 ESTIMATED), 같은 전력 목표에 쓰는 추정(옥상녹화 냉방)을 뺀 남는 양(`after_estimates`, 늘 ESTIMATED, 범위 빼기 [a0, a1] − [b0, b1] = [a0 − b1, a1 − b0]), 가스 쪽 추정(단열·창호 · 옥상녹화 난방)과 승강기(CO2)는 빼지 않고 나란히. 남는 양의 끝이 0 이하면 숫자 대신 '메움'과 여유량. **값과 추정을 한 칸에 더하지 않고, 추정은 목표 · 추천 방안 · 사용자 조합 계산에 들어가지 않음**(남는 양을 추정만큼 줄여 보여 주는 칸이 따로 있을 뿐). 지표 줄은 지역 순서 위 3개를 이유와 함께
- 코드: `backend/app/reduction_plan.py`(3D 사다리), `backend/app/reduction_measures.py`(수단 목록·따로 본 값·내재탄소, `GET /api/reports/measures`), `backend/app/area.py` `recommended_mix`(지역, 태양광만 · 지붕 한도 `reduction_plan.roof_pv` · 남는 양) · `target_bases`(목표 기준 둘), `reduction_measures.applicable_measures`(추천 줄 ↔ 수단 · 근거표). 비용·회수기간은 단가 근거가 없어 계산하지 않고, 출처에 적힌 값만 수단 설명에 옮겨 적는다.

### 5.16 지역난방 열 (추정, 2026-11-20)
- 지역난방 단지는 난방 · 급탕 열을 사서 쓰고, 그 열은 건축HUB · K-apt 어디에도 쓸 만한 사용량이 없다(K-apt `heating_quantity`는 1 m²당 값이 지역마다 수천 배 달라 세대 난방 전체가 아님, 확인 필요). 그래서 열 사용량은 **추정**하고, 관측 전력 · 가스 합계에 섞지 않고 "지역난방 열(추정)"으로 따로 적는다
- 열 사용량 = 계획 연면적 × 대상지 지역난방 연면적 비중(대상지 격자 K-apt 단지, 난방 방식 미상 제외, `service.heating_share`) × 열 원단위
- 열 원단위(kWh/m²) = 같은 지역 · 같은 해 **개별난방 단지 평균 가스 원단위 − 지역난방 단지 평균 가스 원단위**(`service.pooled_baseline` 난방 방식별, 12개월 가스가 다 있어야 함, 개별난방이 더 클 때만). 가정: 지역난방 단지가 사는 열 ≈ 개별난방 단지가 가스로 쓰는 열(서울 181단지 연구에서 지역난방 단지 최종에너지가 개별 대비 +8.8%). 건물에너지사용량통계 ÷ K-apt 비중으로 낸 값은 세종 56.8 · 수원 영통 68.1과 크기가 비슷하지만 두 자료가 어긋나는 곳(수원 장안 705 등)이 있어 쓰지 않음
- 계수 = 공급 지사의 그해 공표값(한국지역난방공사, 2절, "지역난방용 열 사용에 대한 온실가스 배출량 산정시 사용"). CO2eq = CO2 + CH4 × 28 + N2O × 265(AR5, 5.5와 같음), kg/kWh = kg/TJ × 3.6×10⁻⁶. 그해 값이 없으면 계산하지 않음(가까운 해로 채우지 않음)
- 지역 → 지사(그 시군구의 지역난방 공급 지역이 모두 한 지사로 원문 확인된 곳만, `emissions.HEAT_SUPPLIER_BRANCH`): 세종(36110) → 세종지사, 수원(41110) → 수도권 연계지사(수원 · 광교 지사 포함), 대구 달서구(27290) → 대구지사, 양산(48330) → 양산지사. **2026-11-22 더함(새 상세 수집 지역)**: 고양(41280, 고양 · 삼송원흥) · 서울 강남(11680, 수서 · 일원 · 남서울 · 강남보금자리) · 용인(41460, 용인 · 서천) · 파주(41480, 교하 · 운정) → 수도권 연계지사, 김해(48250, 대청 · 유하 · 관동) → 김해지사, 나주(12170, 광주 · 전남 혁신도시) → 광주전남지사. 그 밖의 지역은 열 탄소를 계산하지 않고 5.15의 가정 문장만

## 6. 보고서 작성 기준

1. **숫자는 계산 엔진의 근거 문장에서만** 가져온다. 사람·AI가 새 숫자를 만들지 않는다(앱 보고서는 검증기가 근거에 없는 숫자, 증감 방향 오류, 감축 기준 누락을 막는다).
2. 숫자마다 **단위·연도·출처·값의 종류**(관측/계산/추정/시나리오)를 붙인다. "자료 없음"은 0으로 쓰지 않는다.
3. 감축량을 쓸 때는 **기준(공동주택 K-apt / 건물 전체 건축HUB / 추정)과 기준 연도**를 같은 문단에 쓴다.
4. 증감은 같은 지번(5.7)이나 같은 범위끼리만 말한다. 전후 차이를 원인처럼 쓰지 않는다("개발 때문에" ✕, "개발 전후로" ○).
5. 법적 판단(허가 가능 여부)과 넷제로 달성을 단정하지 않는다.
6. 끝에 **한계**(제공 범위 밖 건물, 결측 연도, 가정값)와 **출처 표**, **재현 정보**를 둔다. 지역 보고서는 보고서 ID와 근거 SHA-256을 적고, 격자(계획안) 검토 보고서는 읽는 사람을 위해 보고서 번호만 적고 근거 SHA-256은 저장 기록(DB 스냅샷)에만 남긴다(2026-10-14). 대상지는 격자 ID가 아니라 지명(예: 전주시 송천1동 일대)으로 적는다.
7. 팀 발표·문서에 다른 팀원의 자료를 쓸 때는 묶음 이름과 기준일을 적는다(예: "urban-carbon 2026-10-01, 탄소공간지도 2024").

## 8. 끝나고 점검

```powershell
docker compose -p carbon-urban-dss -f compose.yaml -f compose.demo.yaml exec -T api python -m app.cli check-standard
# 다른 사람에게 받은 CSV 표를 넣기 전에
docker compose -p carbon-urban-dss -f compose.yaml -f compose.demo.yaml exec -T api python -m app.cli check-standard --csv /data/raw/<폴더>/<파일>.csv
```

`check-standard`는 DB와 파일이 이 문서를 지키는지 셉니다: 음수 사용량(건축HUB·K-apt), K-apt 미보고 달에 남은 양, K-apt 세대당 전기 범위(20~2,000 kWh/월) 밖인데 SUCCESS인 달, 격자 밖인데 MATCHED인 단지, 일사량 표의 빈 자리 행, 전력 계수 표(5.4)와 등록 계수, 냉난방도일 기준온도(5.10), 원본 파일이 `data/raw`에 있는지(파일이 있는지만 봄. 내용 해시는 대조하지 않으니 받은 폴더의 MANIFEST로 따로 확인), 칸 ID 형식, CSV의 인코딩·빈칸 표기·키 중복·단위 없는 숫자 열. 앞의 세 가지는 `apply-standard`가 고칩니다(저장된 달 상태 재판정, OUTSIDE_GRID 표시, 빈 자리 행 삭제). 결과는 `data/ops/standard-check.json`에도 남고, 앱 **사용 방법 → 데이터 기준**에서 볼 수 있습니다. "확인 필요"가 나온 항목은 고치거나, 고칠 수 없는 이유를 작업 기록에 적습니다.
