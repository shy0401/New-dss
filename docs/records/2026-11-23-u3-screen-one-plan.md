- 관련: `frontend/src/pages/AreaPage.tsx`(계획 넣기 · 결과 · 단계 · 근거 자료 접힘 · 묶음 주소 호출 · 보고서 요청), `frontend/src/components/area/TeamAreaPanel.tsx`(입력 폼을 없애고 결과 카드로, 예측 훅 `useTeamAreaPrediction`), `frontend/src/components/area/AreaWorkflow.tsx`(단계 4 → 6), `frontend/src/lib/area.ts`(`PlanState` 용도 줄 · `planBody` · `usesBody` · 묶음 응답 형), `frontend/src/lib/caseLink.ts`(링크에 용도 줄 · 몇 년 뒤 · 건물 모양), `frontend/src/styles/area.css`, 시험 `AreaPage.test.tsx` · `TeamAreaPanel.test.tsx` · `AreaWorkflow.test.tsx` · `lib/area.test.ts` · `lib/caseLink.test.ts`

## 왜
같은 계획을 두 곳에 넣어야 했음: 위 '계획 조건'(연면적 또는 층수 × 동수, 철거)과 접힌 '팀 변화 모델' 칸(용도 · 연면적 · 세대 · 철거 용도 · 몇 년 뒤). 두 값이 달라도 화면이 그대로 계산해, 감축 계산과 변화 모델이 서로 다른 계획을 계산할 수 있었음(그 칸의 "위 계획 조건과 다릅니다" 문구). 결과도 감축 노력 · 행정동 비교 · 접힌 예측 칸에 흩어져 한 줄 결론이 없었음

## 무엇을 바꿨나 (숫자는 서버 값 그대로, kg → t만)
- 계획 넣기(2단계) 한 곳: 용도별 신축 표(1~4줄, 용도는 팀 모델 `Item.use` 10종, 주거 줄에만 세대수) · 철거 표(0~4줄) · 선택 층수 / 동수 / 동당 건축면적 · 몇 년 뒤(1~10, 기본 7). 목표 % · 기준 건물 · kW당 발전량은 접힌 '계산 설정'으로
- 연면적의 원본은 용도 줄의 합 하나: `plan.added_floor_area_m2` = 신축 줄 합, `removed_floor_area_m2` = 철거 줄 합, `uses_new` · `uses_removed`는 같은 줄(연면적 있는 줄만). 층수는 1 이상, 동수 · 동당 건축면적은 둘 다 있을 때만 보냄. 셋이 다 있고 곱이 합과 다르면 서버 422 문장을 계획 칸에 보임(설계 Q9 가)
- 분석 요청: `POST /api/areas/analyze` → `POST /api/plans/evaluate`(같은 본문 + `uses_new` · `uses_removed` · `years_after` · `include` = 변화 모델을 뺀 다섯 블록). 기존 패널은 응답의 `analysis`(analyze와 같은 모양)를 그대로 씀. 값을 바꾸면 다시 계산(450 ms 뒤) · 지역 바꿈 막기(`optionsReady`)는 그대로
- 결과(3단계): 한 줄 결론 = `blocks.plan_emission.text`(엔진 문장, Q2 가) → 세 범위 표(이름 · 범위 글은 응답 `scopes`): 원단위 기반 계획 배출(`effort.targets` `plan_added`의 `net_added_kgco2eq` ÷ 1000, 소수 한 자리) · 팀 변화 모델(아래 카드의 값) · 한 칸 계획안(`/simulation` 링크, 여기서 계산하지 않음) + "더하거나 평균하지 않습니다" 한 줄 → 지역난방 열(추정) 한 줄(`blocks.district_heat`가 OK일 때만, 추정 배지 + 엔진 문장) → 변화 모델 카드 → 필요한 노력 → 행정동 비교
- 변화 모델 카드: 입력 폼과 '위 계획 따라가기'를 없앰. 빠른 답이 돌아오면 그 요청의 구역 칸 · 용도 줄 · 몇 년 뒤로 `/api/team-model/predict-area`를 한 번 부름(Q1 가). 목표 % · 기준 건물 · 발전량만 바뀌면 같은 요청이라 다시 부르지 않음. 표 없는 지역(404) → 까닭 + 원단위 기반 대신 값(U2-0 그대로), 그 밖의 오류는 '다시 예측' 단추. 용도 미정 · 칸 64개 초과 · 칸 없음은 부르지 않고 까닭. 공개 주소는 통째로 숨기던 것을 "이 PC 화면에서만" 한 줄 + 대신 값으로(설계 6.2)
- 1,000 tCO₂e 미만: 카드의 큰 숫자 자리와 세 범위 표에 방향(늘어나는 / 줄어드는)만, 구간 · 에너지원별 구성은 내지 않음(보고서 `change_model_direction` 문장과 같게). 칸별 표(접힘)는 그대로
- 단계 4 → 6: 구역 고르기 → 계획 넣기 → 결과 → 감축 방안 → 배치·상한 (선택, 지금은 한 칸 화면 링크만) → 보고서
- 과거와 현재 · 근거 자료 더 보기(9개) · 개발 전후 영향을 접힌 '근거 자료' 하나에(내용 그대로, 화면 맨 아래)
- 보고서 요청 본문에 `uses_new` · `uses_removed` · `years_after`(서버가 변화 예측 절을 넣음, S2)
- 사례 링크: `plan` · `removed`(합)는 그대로 두고, 있을 때만 `uses=residential:60000:500,commercial:30000` · `ruses=` · `years=`(7이 아닐 때) · `floors=` · `buildings=` · `footprint=`를 뒤에 붙임. 용도 줄 없는 옛 링크(`plan=75000`)는 '용도 미정' 한 줄로 받아 연면적만 보내고 변화 모델은 돌리지 않음(주거로 짐작하지 않음, 설계 2.1)

## 전 → 후 (어디로 옮겼나)
| 항목 | 전 | 후 |
|---|---|---|
| 신축 연면적 | '계획 조건'의 추가 연면적(또는 층수 × 동수 × 건축면적) + 예측 칸의 용도 줄 | 계획 넣기의 용도 줄(합이 곧 연면적) |
| 층수 · 동수 · 동당 건축면적 | '층수 × 동수' 탭(연면적 대신) · 연면적 탭의 층수(선택) | 계획 넣기의 선택 칸(지붕 한도에만, 셋이면 곱 = 합) |
| 철거 | '계획 조건'의 철거 연면적 + 예측 칸의 철거 용도 · 연면적 | 계획 넣기의 철거 표(0~4줄) |
| 몇 년 뒤 · 세대수 | 예측 칸 | 계획 넣기 |
| 목표 % · 기준 건물 · 발전량 | '계획 조건' 왼쪽 | 계획 넣기 안 접힌 '계산 설정' |
| 분석 주소 | `/api/areas/analyze` | `/api/plans/evaluate`(빠른 다섯 블록) |
| 변화 모델 예측 | 접힌 칸에서 단추로 | 빠른 답 뒤 자동, 결과 단계의 카드 |
| 한 줄 결론 · 세 범위 표 · 지역난방 열 한 줄 | 없음 | 결과 단계 맨 위 |
| 필요한 노력(목표 % 기준) | '계획 조건' 오른쪽 | 결과 단계(내용 그대로) |
| 과거와 현재 · 근거 9개 · 개발 전후 | 지도 바로 아래 | 맨 아래 접힌 '근거 자료' |
| 단계 표시 | 4단계 | 6단계 |

숫자: 기본 예시 계획(주거 50,000 m², 건물 모양 없음)이 보내는 `plan`은 전과 같은 `{added_floor_area_m2: 50000}`이라 감축 계산 값은 바뀌지 않음. 바뀌는 것은 화면에 보이는 자리와 변화 모델을 부르는 때뿐
