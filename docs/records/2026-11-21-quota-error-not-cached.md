## 왜 (실측)
- 03:22 K-apt 에너지가 하루 5,000회(개발계정)에 걸려 `LIMITED_NUMBER_OF_SERVICE_REQUESTS_EXCEEDS_ERROR`(코드 22) 응답 3건을 받음. 이 응답이 다른 오류처럼 캐시에 1시간 재사용(`ERROR_CACHE_SECONDS=3600`)됨
- 03:5x 운영계정 승인 뒤 같은 키의 직접 호출은 정상(00)이었는데, 다시 넣은 K-apt 수집은 캐시의 '호출 제한'을 읽고 실제 요청 없이 곧바로 WAITING(마지막 실제 응답 03:22). 캐시의 오류 기록 3건을 지운 뒤 04:19부터 다시 돎
- 같은 일은 하루 한도가 풀리는 다음 날 00:20 자동 재개 때도 생길 수 있음(그 전 1시간 안에 막힌 요청이 있으면)

## 무엇을 바꿨나
- `cache.CachedClient.get`: 호출 제한(HTTP 429 또는 `LIMITED_NUMBER`) 응답은 캐시 파일을 쓰지 않고 바로 오류로 올림(`QUOTA_ERROR`). 예전 판이 써 둔 호출 제한 캐시는 읽지 않고 다시 물음
- 인증 실패 · 다른 오류의 1시간 캐시와 오류 색인은 그대로(시험의 예시만 인증 실패로 바꿈)
