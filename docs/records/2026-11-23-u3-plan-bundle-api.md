# 2026-11-23 계획 하나 → 답 하나: 묶음 응답 주소(`POST /api/plans/evaluate`)
- 관련: 새 `backend/app/plan_bundle.py`, `backend/app/main.py`(라우터), `backend/app/domain.py`(`coverage_ratio_pct`), 시험 `tests/test_plan_bundle.py`, 확인 스크립트 `scripts/bundle_live_check.py`
- 사용자: 계획 추천안대로(사용자 활용 단계 U3, D3 가: 지역 시뮬레이션을 주 입력 화면으로). 설계: Fable high 문서(이 PC `project/working/methods/u3-plan-bundle-design-2026-11-23.md`) 7절 S1
- U4(PR #80, Draft)의 `effort.targets`를 읽으므로 그 위에 쌓음 → #80이 먼저 들어가야 함

## 왜
같은 계획을 세 화면에서 세 번 넣고(지역 시뮬레이션 · 한 칸 시뮬레이션 · 팀 변화 모델 칸), 화면마다 숫자의 범위가 달라(전력만 / 전력 + 가스 / 탄소공간지도 건물 배출) "같은 계획인데 값이 다르다"로 읽힘. 보고서에는 변화 예측이 없었음

## 무엇을 더했나 (백엔드만, 화면은 아직)
- 입력: 지역 분석 입력 그대로 + `uses_new` · `uses_removed`(용도별 연면적 · 세대, 팀 모델 용도 10종) · `years_after` · `site`(대지 중심 · 면적) · `include`. 연면적의 원본은 용도 줄의 합. 층 × 동 × 동당 건축면적과 다르면 422(한 계획에 연면적 둘 없음)
- 블록 여섯(값은 기존 계산에서 꺼내기만, 새 산식 없음): ① 기준 배출(`analyze` 한 번) ② 원단위 기반 계획 배출 = U4 `plan_added` 한 필드 ③ 변화 모델(요청할 때만, 13~29초라 화면이 따로 부름) ④ 감축(U4 두 기준 · 수단 연결) ⑤ 지역난방 열(칸 하나일 때, 기준 문서 5.16 규칙 그대로) ⑥ 조례(지역 규칙, 대지가 있으면 상한 · 계획 판정)
- 블록이 OK가 아니면 숫자는 null + 까닭. 변화 모델 사전 점검: 공개 주소 · 용도 줄 없음(용도를 짐작해 채우지 않음) · 칸 64개 초과 · 지역에 팀 표 없음 · 이 구역 칸이 표 밖 · 서비스 꺼짐 · 학습 중. 예측이 없으면 ②를 가리키는 대신 문장(`fallback`, U2-0 문구의 근거)
- 변화 모델이 1,000 tCO₂e 미만이면 `reading = "direction"`(기준 문서 5.8)
- 세 범위 표(`scopes`): 원단위 기반(전력만) · 지역난방 열(추정) · 변화 모델(탄소공간지도 건물 배출) · 한 칸 계획안(전력 + 가스) — 섞지 않고 나란히
- 목표 %를 안 넣으면 ④는 개발 증가분 기준만(구역 전체 목표는 내지 않음)
- 정할 것 Q1~Q10은 설계 추천안대로(Q3 지역난방을 구역 단지 전체로 넓히는 것은 기준 변경이라 하지 않음)

## 확인
- 시험 9개(DB 없이, CI와 같게): 용도 줄 합 = 연면적, ②는 U4 필드 그대로, 연면적 둘이면 422, 목표 없음, 공개 주소 · 용도 없음 · 팀 표 없는 지역은 서비스를 부르지 않음, 1,000 t 미만은 방향만, 지역난방은 칸 하나 필요, 비율 식
- 실제 DB 한 번(전주 칸 하나, 주거 50,000 m² · 20층 × 5동 × 500 m², 대지 20,000 m², 목표 40%): 6블록 모두 응답. 기준 1,968,311 kg(관측) · 증가분 577,213.3 kg · 변화 모델 +1,264.9 tCO₂e(구간 433.6~2,145.5) · 지역난방 없음 · 조례 용적률 상한 217.91% 대 계획 250% · 감축 두 기준 모두 태양광 150 kW(지붕 한도) + 남는 양. 분석 45초(빈 캐시 첫 호출, 다른 측정과 함께), 변화 모델 2초

## 검토 뒤 고친 것 (Fable 코드 검토)
- 목표 %가 없을 때: 엔진은 증가분만 얻으려고 0%로 돌리고, 구역 전체 목표에 딸린 문장 · 필드(0% 목표 문장, 구역 전체 기준, 추천안, 사용자 조합, 곡선, 업계 대조)를 응답 전체에서 뺌
- 계획이 없으면 ②는 `NO_PLAN`과 null(0이 아님). 철거만 있으면 ⑤는 `NO_NEW_FLOOR_AREA`
- 층 × 동 × 건축면적만 넣어도 연면적을 채워 용적률 판정이 됨. 용도 줄은 있는 쪽(신축 / 철거)만 대신함. 연면적 비교는 상대 1%(반올림한 계획을 거절하지 않게)
- 대지 칸이 구역 밖이면 지역난방에 쓰지 않음
- 변화 모델: 사전 점검만 짧은 DB 연결로 하고 서비스 계산(13~29초) 동안은 연결을 잡지 않음. 서비스 오류는 모두 `ERROR`로 잡아 다른 블록은 그대로, 변화량 없는 답도 `ERROR`, 서비스 `unavailable`은 `UNAVAILABLE`, 칸 없음은 `NO_CELLS`
- 조례: 상태마다 같은 키, 엔진 상태(`NO_ZONING` 등)에 까닭 문장, "구역 전체 연면적을 대지 한 곳에" 본다는 주석. 공동주택 상한은 주거 용도 줄이 있을 때(용도 줄이 없으면 공동주택으로 봄)
- 시험 14개(DB 없이)
