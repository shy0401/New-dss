# 2026-11-22 기상만 따로 받기(Open-Meteo 하루 한도 시각 고침)
- 관련: `region_prepare.next_open_meteo_reset` · `resume_time` · `step_weather`, `tasks._run_region_locked`(단계마다 다시 받을 시각), 시험 `tests/test_weather_quota.py`
- 사용자: 수집을 핵심 34위에서 멈춘 뒤 "기상만 받기", 이어서 "한도가 풀린 후의 수집된 데이터가 반영될 수 있도록 하고 다음 작업으로"

## 왜
- 핵심 34위에서 멈춘 뒤([기록](2026-11-22-national-run-stop-at-core.md)) 기상이 없는 지역은 지역 화면 가이드의 태양광 줄이 '자료 없음'([기록](2026-11-22-region-guide-local-heating-solar.md))
- 기상(Open-Meteo, 키 없음)은 다른 갈래(K-apt · VWorld · 건축HUB)와 따로 받을 수 있어 기상 단계만 다시 넣음

## 무엇이 틀렸고 무엇을 고쳤나
| 항목 | 비포 | 애프터 |
|---|---|---|
| 한도에 걸린 뒤 다시 받는 시각 | 다음 날 00:20 KST(공공데이터 한도 기준) → 11/22 00:20에 다시 물었다가 또 한도(429 "Please try again tomorrow") | Open-Meteo는 세계 표준시 자정에 풀림 → **00:05 UTC(09:05 KST)**. 11/22 13:52 KST에는 풀려 있었음(확인) |
| 기온은 받고 일사량 요청에서 한도 | 일사량 없이 기상 DONE으로 끝남(속초 51210, 11/21 14:39 KST: "일사량 0개월") | 기다림(WAITING)으로 두고 위 시각에 다시 받음(기온 답은 캐시에서) |
| 기다림 문구 | 공공데이터 하루 한도 문구 | "Open-Meteo 하루 호출 한도 — 세계 표준시 자정(09:00 KST) 뒤 다시 받음" |

## 숫자(11/22 15시 무렵, DB 기준)
| 기상 단계 | 지역 수 | 가이드 태양광 |
|---|---|---|
| DONE | 170(오늘 13:52~14:37에 31곳 받음, 139 → 170) | 169곳 나옴, 속초 1곳 없음 → 11/23 09:05 다시 받기 예약 |
| SKIPPED(전주, 원래 지역 자료) | 1 | 나옴 |
| WAITING | 54 | 없음 → 11/23 09:05 KST 자동 재개(54곳 모두 `resume_at` 00:05 UTC 확인) |
| PENDING(인천 새 구 4곳, 빼 둠) | 4 | 없음 |

- 하루에 받는 양: 약 30~40곳(지역마다 11년치 일별 기온 + 일사량, 무거운 요청 2건). 남은 54곳은 11/23~24 예상
- 반영: 가이드 태양광은 요청마다 DB에서 바로 계산(`solar.regional_pv_yield`, 캐시 없음) → 받는 즉시 화면에 나옴(따로 할 일 없음). 이번에 받는 지역은 모두 PARTIAL이라 구역 분석(READY 지역) 입력 캐시와는 관계없음
- 계산 · 기준 바뀜 없음(기준 문서 판 그대로)
