# 작업 · 수치 · 변화 기록

모델 · 자료 · 화면 · 기준을 바꿀 때마다 **무엇을, 왜 바꿨고, 숫자와 화면이 어떻게 달라졌는지**를 한 곳에 남깁니다.
코드와 PR만 보면 "무엇이 바뀌었는지"는 알 수 있어도 "왜, 어떤 근거로, 숫자가 얼마나"는 흩어져 있어서 나중에 다시 찾기 어렵습니다.
이 폴더는 그 흐름을 사람이 읽는 글로 모아 둡니다. 기준 자체는 [공통 데이터 기준](../DATA_STANDARD.md), 팀 모델의 설정은 [팀 데이터셋](../TEAM_DATASET.md)이 원본이고, 이 폴더는 **바뀐 이력**을 적습니다.

## 언제 남기나
- 모델의 입력 · 학습 · 평가 방법이 바뀔 때
- 서비스나 화면이 보여 주는 숫자 · 문구가 바뀔 때
- 자료의 범위 · 제외 규칙 · 계수가 바뀔 때
- 시험 결과로 무언가를 채택하거나 보류 · 기각했을 때(기각도 남깁니다. 같은 시도를 되풀이하지 않게)
- 사용자 · 팀이 방향을 정했을 때

## 파일 규칙
- 파일 이름: `YYYY-MM-DD-주제.md`(영문 소문자 · 하이픈). 한 작업 묶음(보통 PR 하나)에 한 파일
- 사람 이름을 쓰지 않습니다. 결정한 쪽은 "사용자", "팀"으로 적습니다([AGENTS.md](../../AGENTS.md))
- 숫자는 시험 · 계산 결과에 근거가 있는 것만 적고, 기준(칸 · 개발 단위, 교차검증 · 시험, 범위, 시드 수)과 출처를 함께 적습니다
- 관측 · 계산 · 추정 · 시나리오를 섞지 않습니다
- 국토통계지도처럼 반출이 안 되는 자료나 그 자료로 만든 화면 캡처는 넣지 않습니다. 화면 변화는 글과 표로 적습니다

## 한 기록의 양식
```markdown
# YYYY-MM-DD 주제
- 관련: PR 번호, 바뀐 파일, 기준 문서 절
## 왜
## 무엇을 바꿨나 (비포 → 애프터)
| 항목 | 비포 | 애프터 | 근거 |
## 숫자 (기준을 함께)
## 결정 (누가 무엇을 정했나)
## 하지 않은 것 · 보류한 것과 이유
## 남은 일 · 한계
```
