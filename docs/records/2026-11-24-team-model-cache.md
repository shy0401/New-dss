# 2026-11-24 팀 변화 모델: 학습한 모델을 저장해 다음 시작 때 불러오기
- 관련: `deploy/team-model/server.py`(`model_cache_key` · `load_model` · `save_model`), `compose.yaml`(볼륨 `team_model_cache`), 시험 `tests/test_team_model.py::test_saved_model_is_reused_only_while_every_input_is_the_same`, [팀 데이터셋](../TEAM_DATASET.md), [한계](../LIMITATIONS.md). 앞 기록: [VmmemWSL · dropcache](2026-11-24-wsl-dropcache.md)
- 계기: 사용자 — 남은 메모리 항목을 현재 상태를 백업해 두고 진행, 결과가 바뀌면 백업으로 되돌리는 방식으로

## 왜
- 팀 모델은 Docker를 켤 때마다 다시 학습했다: 약 2.5분, 그동안 메모리 순간 최대 2.34 GB, 변화 모델은 답하지 않음(오늘 시험 중에도 변화 모델이 비어 나옴)
- 같은 입력이면 같은 모델이 나온다(학습 seed 고정). 한 번 학습한 것을 두고 다시 쓰면 된다

## 백업과 판단 규칙 (바꾸기 전에 정함)
- 백업: main 그대로(새 브랜치에서 작업), 이미지 이름표 `carbon-urban-dss-{api,team-model,worker}:before-peak-2026-11-24`
- 기준 결과: 계획 평가 3곳(전주 · 수원 · 장수) 응답 전체, 지도 3곳, 팀 모델 직접 예측 4건(구역 3 · 칸 계획 1, 그중 2건은 팀 표에 없는 지역의 404), 팀 모델 상태(입력 설명). 두 번 저장해 서로 다른 칸 0개 확인(같은 입력 = 같은 답)
- 규칙: 시각 기록 칸만 빼고 모든 칸이 같음 + 시험 통과 + 첫 조회가 기준 범위보다 느리지 않음. 하나라도 어긋나면 되돌리고 기각으로 남김
- 비교 도구: `project/tools/experiments/peak_baseline_2026-11-24.py`(PC), 결과 `data/derived/peak_baseline_2026-11-24/`(Git 밖)

## 무엇을 바꿨나
- 학습이 끝나면 모델 객체를 Docker 볼륨 `/cache`에 pickle로 저장(166 MB). 다음 시작 때 열쇠가 같으면 불러옴
- 열쇠: 서버 폴더 파일(.py · .csv 내용), `TEAM_*` 설정, 팀 코드 `src/` · `config/` 내용, 학습 폴더 파일의 크기 · 수정 시각, 라이브러리 판. 하나라도 바뀌면 다시 학습하고 옛 파일은 지움
- `data/`가 아닌 Docker 볼륨에 두는 이유: 학습 표에 국토통계지도 값이 있음. 묶음 · 백업 스크립트는 볼륨을 파일로 담지 않음(확인)
- `TEAM_MODEL_CACHE=off`면 예전처럼 매번 학습. 파일이 깨졌거나 저장이 안 되면 학습한 모델로 계속 답함(`/status`의 `model_cache`에 상태)
