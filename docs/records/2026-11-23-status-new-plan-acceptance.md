# 2026-11-23 현황 정리: 새 개발 계획을 넣으면 무엇이 나오나 · 사용자 흐름 합격 시험(5개 지역)
- 관련: 바뀐 코드 · 계산 없음(현황과 시험 결과 기록). 시험 도구 · 결과는 이 PC `project/tools/experiments/acceptance_2026-11-23.py` · `eval/acceptance_2026-11-23/`
- 사용자: 발표(11-27) 전에 "지역 + 새 개발 입력 → 탄소 변화 예측 → 지역 조건을 반영한 감축량"이 문제없이 나오는지 확인, 오늘 정리한 내용을 기록으로 남김

## 1. 사용자가 받는 것 (새 개발 계획, 2026-11-23 기준)
| 결과 | 어떻게 | 범위 · 한계 |
|---|---|---|
| **원단위 기반 증가분** | 구역 건물의 관측 전력(건축HUB · K-apt, 12개월 완비) ÷ 대장 연면적 = 원단위(5.2) → 원단위 × (신축 − 철거) × 전력 계수(5.9) | READY 56곳 모두. 전력만(가스 · 지역난방 제외), 새 건물이 지금 건물과 같은 원단위라고 가정한 **시나리오**. 입력은 모두 관측 · 공식 자료 |
| **감축량** | 목표 기준 둘(개발 증가분 상쇄 · 구역 전체 목표 %), 지붕 태양광(지역 일사량 × 0.80, 계획 지붕 한도까지) + 남는 양, 쓸 수 있는 수단과 근거 | 값이 있는 수단은 태양광뿐, 나머지는 지표만(근거 부족으로 값 비움). 56곳 모두 |
| **팀 변화 모델 예측** | 53개 지역 과거 개발 사례로 학습한 모델이 칸의 개발 전 상태 + 계획 → 건물 배출(전기 · 가스 · 지역난방) 변화와 80% 구간 | 칸 상태 표가 있는 곳만(아래 2절). 1,000 t 미만은 방향만 |

- 두 값(원단위 · 변화 모델)은 범위가 달라 더하거나 평균하지 않고 나란히 둠

## 2. 변화 모델이 되는 지역 · 안 되는 지역 (READY 56곳, 각 지역 기본 대상지 칸)
- **됨 21곳**: 송파 · 강동 · 강서 · 동구 · 북구 · 수성 · 달서 · 연수 · 세종 · 수원 · 고양 · 과천 · 남양주 · 오산 · 하남 · 용인 · 파주 · 화성 · 경산 · 김해 · 전주
- **일부 칸만 2곳**: 성남 · 안산(같은 시의 다른 구 표만 있음)
- **안 됨 33곳**: 강남 · 양천 · 안양 · 부천 · 제주 · 서귀포 · 군산 · 익산 · 정읍 · 완주 · 장수 등
- **안 되는 까닭**: 모델 능력이 아니라 **입력(그 칸의 현재 모습: 건물 · 용도지역 · 인구 · 기상)을 서비스가 팀 데이터셋 표에서만 읽기** 때문. 그 지역의 과거 개발 자료는 필요 없음(다른 지역 사례에서 배운 패턴으로 예측: 지역을 빼고 잰 교차검증 오차 0.298, 학습에 안 쓴 시험 10지역 0.225). 안 되는 곳도 원단위 증가분 · 감축량은 나오고, 변화 모델 자리에 까닭과 대신 값이 나옴
- 해결: U2-c(우리 DB의 공개 자료로 칸 상태 표를 만들어 연결). 모델 단위 대조 통과(중앙 차 0.7%, [기록](2026-11-23-u2c-model-compare-vworld-keys.md)). 서비스 반영은 큰 모델 변경이라 발표 뒤
- **출발 해**: 칸마다 팀 표에서 "학습에 쓸 수 있는" 가장 최근 해. 팀 학습 표의 2024년 행은 49.5%만 쓸 수 있어(전주 24%, 2022년 56%) 전주 · 수원 시험 칸은 **2021년 상태 → 7년 뒤 2028년**으로 예측함(앞서 "2024년 출발"로 설명한 것은 틀림 — 이 기록이 맞음). 2024년 행이 빠지는 까닭은 팀 규칙의 제외 표시(자세한 까닭 확인 필요)

## 3. 무엇이 팀 자료이고 무엇이 우리 수집인가
- 팀 데이터셋(팀원이 만든 urban-carbon 묶음, 10-29 판): 53개 지역 × 7개 해 학습 표(국토통계지도 100m · 대장 · SGIS · 용도지역 + 정답 탄소공간지도), 개발 사례, 모델 코드
- 변화 모델에 얹은 우리 몫: 기상(같은 시 ASOS · AWS, `station_annual.csv`), 2024년 전력 계수 맞춤, 칸 단위 급감 재판정, 예측 구간(교차검증 잔차), 계획 → 입력 · 구역 나눔
- 원단위 계산 · 감축량은 거의 전부 우리 수집(K-apt · 건축HUB 에너지 · 기상 · 일사량 · VWorld · 대장)

## 5. 사용자 흐름 합격 시험 (실제 서비스, 같은 새 개발 입력)
- 입력: 주거 60,000 m²(600세대) + 상업 20,000 m², 20층, 7년 뒤, 목표 30%, 각 지역 기본 대상지 칸(500m 1칸). 보고서는 만든 뒤 바로 지움(DELETE 204 → 다시 읽으면 404)

| 지역 | 첫 화면 합계 | 원단위 증가분(t/년) | 변화 모델 | 감축: 필요(증가분 · 구역 전체, t) / 태양광 | 지역 조건 | 보고서 | 공개 주소 |
|---|---|---|---|---|---|---|---|
| 전주 | 6,571.2 t | 1,047.2 | **+2,748 t (942~4,661), 2021 → 2028** | 1,047 · 1,731 / 240 kW(지붕 한도) + 남는 양 | 일사량 ASOS 146 관측 1,199.9 kWh/kW · 지역난방 없음 | 변화 절 · 같은 값 | 변화 모델 숨김 · 나머지 나옴 |
| 수원 | 1,626.5 t | 949.1 | **+2,347 t (805~3,981), 2021 → 2028** | 949 · 3,854 / 240 kW | ERA5 1,176.4(재분석 표시) · 지역난방 열 300.4 t | 같음 | 같음 |
| 성남 | 3,692.2 t | 988.5 | 까닭(다른 구 표만) + 대신 값 | 989 · 5,114 / 240 kW | ERA5 1,162.6 · 지역난방 열 810.6 t | 변화 절에 까닭 | 같음 |
| 강남 | 12,846.2 t | 1,139.4 | 까닭(팀 표 없음) + 대신 값 | 1,139 · 3,296 / 240 kW | ERA5 1,162.6 · 지역난방 열 528.7 t | 변화 절에 까닭 | 같음 |
| 장수 | **빈칸**(가스 관측 없음) | 1,185.0 | 까닭(팀 표 없음) + 대신 값 | 1,185 · 1,298 / 240 kW | ERA5 1,216.0 · 지역난방 없음 | 변화 절에 까닭 | 같음 |

- 판정: **5곳 모두 흐름이 끊기지 않음**(오류 응답 0, 값이 없을 때 0이나 음수로 채운 곳 없음, 화면 값 = 보고서 값, 공개 주소에서 변화 모델만 숨김)
- 한계(발표에서 "현재 범위"로 말할 것)
  1. 변화 모델은 21곳(+일부 칸 2곳). 나머지는 까닭과 원단위 대신 값
  2. 변화 모델 출발 해가 칸마다 다름(시험 칸 2021년)
  3. 감축 수단 값은 지붕 태양광뿐. 80,000 m² · 20층 계획이면 지붕 태양광(240 kW)이 메우는 몫은 증가분의 10.6~12.9%(5곳), 나머지는 "남는 양"
  4. 조례 상한은 대지(중심 · 면적)를 넣어야 나옴(시험은 대지 없이 → `NEEDS_SITE`)
  5. 장수처럼 기준 단지에 가스 관측이 없으면 첫 화면 합계가 빈칸(0으로 채우지 않음)
  6. 속도: 묶음 응답 4~45초(수원 45초 = 분석 25초 + 지역난방 17초), 화면에서 행정동(19칸) 첫 계산 48초 + 변화 모델 12초
- 화면 확인(전주 송천1동, 행정동 19칸): 계획 넣기 → 결과 → 세 범위 표, 변화 모델 카드 +6,145 tCO₂e/년(2,107~10,424), 오류 응답 0
