# 2026-11-24 Docker 메모리: 한도 대신 쓸데없이 쥔 메모리 돌려주기
- 관련: `backend/app/memtrim.py`(새 파일), `main.py`(무거운 요청 뒤), `tasks.py`(1초 넘은 작업 뒤), `deploy/team-model/server.py`(학습 뒤 · 예측 뒤), `compose.yaml` 설명, [팀원 PC 재현](../TEAM_SETUP.md) 1절, 시험 `tests/test_memtrim.py`. 앞 기록: [Docker 메모리 줄이기](2026-11-24-docker-memory.md)(#112)
- 계기: 사용자 — 32 GB에 맞춰 한도를 거는 게 아니라, 노트북에서도 동작에 문제가 없다는 전제로 쓸데없이 넘치는 사용량을 줄여야 함

## 왜
- 앞 기록(#112)은 VM에 8 GB 고정 한도를 권했다. 그런데 측정용 프로세스가 잠깐 4.5 GB를 더 쓰자, 놀던 팀 모델 1.1 GB가 스왑(디스크)으로 밀려났다(VM 스왑 1.5 GB). 다음 예측이 느려지는 쪽이라 고정 한도는 동작을 해칠 수 있다
- api 메모리를 나눠 보니(같은 계산을 컨테이너 안 별도 프로세스로):

| 몫 | 크기 | 판단 |
|---|---|---|
| 프로세스 RSS(끝난 뒤) | 1,098 MB | |
| `malloc_trim(0)` 한 번으로 돌아온 몫 | 406 MB(37%) | glibc가 해제된 메모리를 쥐고 있던 것. 줄일 대상 |
| 모듈 캐시(직렬화 크기, 지역 3곳) | 약 100 MB(`area._INPUTS` 47 · `_PARCEL_GRID` 23 · `_REGISTER_AREA_CACHE` 13 · `kcsm100._CELLS` 8.5) | 모두 칸 수 한도가 이미 있음(3 · 12 · 16 · 8). 그대로 |
| 파이썬 살아 있는 메모리 | 476 MB(계산 중 최대 1,065 MB) | 계산 자체의 몫 |

- `MALLOC_ARENA_MAX=2`는 효과 없음(끝난 뒤 1,401 MB)

## 무엇을 바꿨나
| 항목 | 비포 | 애프터 |
|---|---|---|
| api | 해제된 메모리를 쥐고 있음 | 1초 넘은 요청이 끝나면 `malloc_trim(0)`(이벤트 루프 밖, 동시에 하나만) |
| 워커 | 같음 | 1초 넘은 작업이 끝나면 같은 처리(워커를 다시 지을 때 적용) |
| 팀 모델 | 같음 | 학습 뒤(gc 포함) · 예측마다 같은 처리 |
| 권장 `.wslconfig` | `memory=8GB` · `swap=8GB` · `autoMemoryReclaim` | `autoMemoryReclaim=gradual`만. VM 한도는 두지 않음(기본값 PC 메모리의 절반) |
| postgres `mem_limit: 3g` | "32 GB PC 기준" | 그대로 둠: PC 크기와 무관한 상한(DB 프로세스 자체는 수백 MB, 나머지는 캐시) |

## 숫자 (같은 계산: 지역 3곳 계획 평가 + 대시보드 2곳)
| | 비포 | 애프터 |
|---|---|---|
| api 끝난 뒤 | 1,267 MiB | 804 MiB(−37%) |
| api 계산 중 최대 | 2.5 GB(이전 관측) | 1,768 MiB |
| 팀 모델 학습 뒤 | 886 MB | 519 MB(−41%). 학습 중 최대 2.36 GB는 그대로 |
| 팀 모델 예측 3번 뒤 | 886 MB | 523 MB |
| postgres 최대 | 2.7 GB | 2.5 GB |

- 계산 결과 같음: 전주 1,633.7 t/년 · 변화 모델 +2,748 t(942~4,661), 수원 1,697.7 t/년 · +2,347.2 t, 저장값과 다른 칸 38개(이미 아는 근거 건수 · 연도별 기상)
- 시험: 컨테이너 637 통과 · 6 건너뜀(새 시험 4개 포함)
- 워커는 09:05 기상 수집 예약 80건을 쥐고 있어 다시 짓지 않음. 수집 뒤 다시 지을 때 적용되고 그때 잰다

## 하지 않은 것 · 이유
- 계산 중 최대(api 1.07 GB 파이썬 몫, 팀 모델 학습 2.36 GB) 줄이기: 계산 방법을 바꿔야 해서 값이 바뀔 위험. 이번에는 하지 않음
- 캐시 칸 수 더 줄이기: 이미 지역 3곳 안팎이고, 줄이면 다시 여는 지역이 처음처럼 느려짐
- jemalloc으로 바꾸기: 이미지에 새 라이브러리가 필요. `malloc_trim`으로 같은 몫을 돌려받아 필요 없음

## 남은 일
- 이 PC의 `.wslconfig`에서 `memory=8GB` · `swap=8GB`를 빼는 것은 `wsl --shutdown`(모든 컨테이너 다시 시작)이 필요해 09:05 수집 뒤 워커를 다시 지을 때 함께 한다
