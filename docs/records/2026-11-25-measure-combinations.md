# 2026-11-25 감축 수단 조합 제안 세 가지(태양광 수준별, 값과 추정을 섞지 않음) (계획 v3 단계 I)
- 관련: `backend/app/reduction_measures.py`(`combinations`), `area.py`, `plan_bundle.py`. 앞 기록: [추정 범위](2026-11-25-estimated-ranges.md) · [태양광 세 수준](2026-11-25-pv-three-levels.md) · [구조 판정](2026-11-25-structure-check.md)
- 계기: 사용자 — 감축을 하나(태양광)에 치중하지 않고 지역 특징에 맞게 여러 방법을 제시(계획 v3). 지금 감축 제안은 "지붕 태양광으로 메우고 남는 양" 하나뿐

## 규칙 (구현 · 결과 보기 전에 정함, 2026-11-25)
- 대상: 개발 증가분 기준(`plan_added`)의 필요 감축량 `need`(전력 운영탄소, kgCO2eq/년). 구역 전체 기준은 이번에 만들지 않음(기존 건물 몫은 근거가 신축 비교라)
- 조합 셋 = 태양광 수준 셋: A 지붕 최대(값) · B 인증 수준(추정 범위) · C 실제 사례 수준(추정 범위)
- 조합마다 칸을 **나눠서** 냄 — 한 칸에 값과 추정을 더하지 않음:
  | 칸 | 내용 |
  |---|---|
  | `pv` | A: 값(kgCO2eq, `data_class` SCENARIO) · B/C: 범위(ESTIMATED) |
  | `after_pv` | need − pv(A는 값, B/C는 범위). 0 아래면 0이 아니라 "메움"과 여유량 |
  | `electricity_estimates` | 같은 전력 목표에 쓸 수 있는 추정: 옥상녹화 냉방 몫(kgCO2eq 범위, 중부2만). 승강기 회생제동은 단위가 CO2라 여기 넣지 않고 `co2_estimates`에 따로 |
  | `after_estimates` | after_pv − 전력 추정 범위 → 범위(ESTIMATED, "추정을 반영하면"). 전력 추정이 없으면 None |
  | `gas_estimates` | 단열·창호(가스) · 옥상녹화 난방 — 전력 목표 밖이라 빼지 않고 "가스 쪽에서 더 줄일 수 있는 양(추정)"으로 나란히 |
  | `indicators` | 지표 줄의 지역 순서 위 3개(단계 B 순서, 이유 문장 그대로) — 값 없음 |
- 범위 빼기: [a, b] − [c, d] = [a − d, b − c](가장 넓게)
- 태양광 · 추정이 없으면 그 칸 None과 이유. 세대 수가 없으면 B/C는 이유만
- 조합은 기존 목표 · 추천 방안 · 사용자 조합 · 감축 제안 줄 어디에도 영향 없음(새 칸 `effort_result.combinations`)

### 확인 (결과 보기 전에 정한 것)
- 조합 칸 말고 응답의 다른 칸은 바꾸기 전과 같음(6개 지역 · 사례 대상지 칸별 비교), 고정 사례 25/25
- 사례 대상지 세 곳의 조합 A/B/C 표를 남김. A의 after_pv는 지금 추천 방안의 남는 양과 같아야 함(같은 지붕 최대)

### 독립 검토 뒤 고친 것 (막는 문제 2)
| 지적 | 고친 뒤 |
|---|---|
| (막음) 층수 · 동 정보가 없어 지붕이 위 한계뿐인 계획에서 A가 "메움"(지붕 태양광 줄은 값을 확정하지 않는데 어긋남) | A는 추천 방안의 판정을 따름: MET · PARTIAL만 값, 그 밖(위 한계 · 지붕 없음 · 발전량 없음)은 값 없이 지붕 태양광 줄과 같은 이유 |
| (막음) 기준 문서 5.15에 조합 규칙이 없음 — "추정은 어떤 합계에도 넣지 않음"과 새 칸이 어긋나 보임 | 5.15에 조합 셋 줄(칸 나눔 · 범위 빼기 · 추정은 목표 · 추천 방안 계산에 들어가지 않음), 판 1.63 |
| A가 반올림한 값끼리 빼 추천 방안의 남는 양과 0.1 차이 · 경계에서 판정 뒤집힘 | A는 추천 방안의 남는 양 · 여유 · "적어도" 표시를 그대로 |
| 지붕 없음(NO_ROOF)이면 이미 아는 남는 양(필요량 전부)이 가려짐, 그런데 인증 · 사례 수준은 지붕 없이 나옴(E 연결 문제) | NO_ROOF는 남는 양 = 필요량 전부, 지붕 한도 0이면 인증 · 사례 수준을 내지 않음(이유 문장) |
| None을 "자료 없음"과 "메움" 두 뜻으로 씀, 0 < v < 0.05가 0.0 값으로 | 끝마다 반올림 뒤 판정, `covered`("all" · "possible" · "no")와 여유 범위 |
| 조합 칸에 추정의 근거 · 조건이 빠짐(추가성 조건 등) | 항목마다 `data_class` · `basis` · `condition` · `scope`, 태양광 수준에 `source_type` · `basis` · `capped` |
| 조합이 없을 때 이유 없음, MET 여유의 뜻 | `combinations_reason`, "필요 용량을 10 kW 단위로 올린 몫" 문장 |
- 남긴 것: 녹지 상쇄(OFFSET, kgCO2)는 조합에 넣지 않음(상쇄라 목표 대응과 따로 보여 줌)

## 결과 (고친 최종판, 600세대 · 주거 60,000 + 상업 20,000 m² · 20층, 개발 증가분 기준 · 단위 t/년)
| 대상지 | 필요 감축(전력) | A 지붕 최대 → 남는 양 | B 인증 → 남는 양(추정) | C 사례 → 남는 양(추정) | 옥상녹화 냉방까지(추정) | 가스 쪽(나란히, 추정) | 승강기(CO2, 나란히) |
|---|---|---|---|---|---|---|---|
| 전주 에코시티 | 1,603.3 | 124.7 → 1,478.7 | 62.3~124.7 → 1,478.7~1,541.0 | 40.5~124.7 → 1,478.7~1,562.8 | A 기준 1,478.6~1,478.6 | 단열·창호 54.9~97.0 · 옥상녹화 난방 1.9~2.6 | 4.1~16.1 tCO2 |
| 부산 명지 | 1,431.3 | 134.5 → 1,296.9 | 67.2~134.5 → 1,296.9~1,364.1 | 43.7~134.5 → 1,296.9~1,387.6 | 없음(남부) | 단열·창호 7.5~13.2 | 4.1~16.1 tCO2 |
| 수원 호매실 | 1,763.4 | 122.3 → 1,641.1 | 61.1~122.3 → 1,641.1~1,702.2 | 39.7~122.3 → 1,641.1~1,723.6 | A 기준 1,641.0~1,641.1 | 단열·창호 10.2~18.0 · 옥상녹화 난방 0.4~0.5 | 4.1~16.1 tCO2 |
- A의 남는 양 = 추천 방안의 남는 양(같은 값, 규칙대로). 지표 위 3개: 전주 신축 통합 기준 · 세대 표시장치 · 공용 조명(지자체 과제), 부산 지역난방 제어 · 외부 차양 · 신축 통합, 수원 지역난방 제어 · 패시브 · 열회수 환기(난방도일)
- **놀란 점 · 발표 · 보고에 쓸 메시지**: 이 계획(신축 80,000 m²)의 전력 증가분 1,431~1,763 t에 견주면 지붕 태양광은 7~9%, 옥상녹화 냉방은 0.1 t도 안 됨. 가스 쪽 단열·창호(전력 목표 밖)도 전주 55~97 t. 즉 **건물 안 수단을 다 써도 개발 증가분의 대부분은 남음** → 구역 밖 재생에너지 · 기존 건물 감축 · 계획 규모 자체가 남는 양을 좌우. 조합이 이 차이를 숫자로 보여 줌
- 바꾸기 전(G 최종)과 비교: 6개 지역 · 사례 대상지 모두 다른 칸은 `combinations`(지역마다 2칸 = 분석 · 감축 블록)뿐, 고정 사례 25/25, 시험 802 통과(먼저 쓴 45개 + 검토 뒤 3개)
- 같은 PR에서 고친 E 연결: 새 지붕이 없으면 태양광 인증 · 사례 수준을 내지 않음(지붕 한도 0)
