# 2026-11-23 변화 모델이 없는 지역: "없습니다" 대신 까닭과 원단위 기반 증가분
- 관련: `backend/app/team_model.py`(`predict_area`가 서비스에 묻기 전에 까닭을 냄, `NO_TEAM_TABLE` · `NOT_IN_TEAM_CELLS`), `frontend/src/components/area/TeamAreaPanel.tsx`(대신 값 칸), `frontend/src/pages/AreaPage.tsx`(`intensityFallback`), `frontend/src/lib/area.ts`(`EffortTarget` 형), 시험 `tests/test_team_model.py`, `TeamAreaPanel.test.tsx`
- 사용자: 계획 추천안대로(사용자 활용 단계 D2 가: 시험 결과가 나오기 전 새 지역 화면은 원단위 기반 값을 "변화(원단위 기반)"로 대신 보임). U4(#80) · U3 S1 위에 쌓음(U4 `plan_added` 필드를 읽음)

## 왜
- READY 56곳 중 37곳은 팀 데이터셋(칸 상태 표)이 없어 지역 화면의 "이 구역 배출 변화 예측"을 누르면 서비스까지 가서 "팀 데이터셋에 지역 41130이(가) 없습니다(53개 지역만)"가 뜸. 성남처럼 같은 시의 다른 구(41131 수정구)만 표에 있으면 더 헷갈림
- 사용자 방향: "예측을 줄 수 없다고 하면 안 됨". 모델 쪽 해결(U2-c)은 시험이 통과했으나 서비스 반영은 따로(Draft) → 그 전까지는 같은 계획의 원단위 기반 증가분을 범위를 밝혀 대신 보임

## 무엇을 바꿨나
- 백엔드: 구역 예측에서 칸이 든 팀 표 지역을 못 찾으면, 서비스에 묻기 전에 404로 까닭을 냄 — 지역에 표가 없음 → "이 지역은 팀 데이터셋(칸 상태 표)이 없어 … 아직 내지 못합니다(준비 중). 원단위 기반 계산 값을 참고하세요", 같은 시 다른 구 표만 있음 → "… 이 구역의 칸은 팀 데이터셋 밖 …". 팀 격자 표가 없는 실행 환경(시험 · CI)은 전처럼 서비스가 답함
- 화면(지역 화면 팀 변화 모델 칸): 예측이 실패하면 오류 문장 아래에 "변화 모델 예측 대신(다른 범위): 원단위 기반 계산" 칸 — 이 계획으로 늘어나는 전력 운영탄소(U4 `plan_added.net_added_kgco2eq`, 위 감축 노력과 같은 값), 기준 연도, "변화 모델(탄소공간지도 건물 배출)과 범위가 달라 견주거나 더하지 않음"
