# 2026-11-21 api 시작 예열을 가볍게: 구역 입력이 지역 건축물대장만 읽음
- 관련: `area.load_inputs`, `main._warm_caches_in_background`, [감시 작업](2026-11-21-region-watchdog.md)
- 사용자: "예열 가볍게 고치는 방향으로 진행해"

## 왜 (실측, 2026-11-21 전국 수집 중)
- api 본체가 시작 뒤 최고 29.4GiB(VmHWM)까지 올라감. 다시 띄운 뒤 들어온 요청은 `/api/health`뿐이라 원인은 시작 예열
- 예열 단계를 메모리 6GiB로 묶은 일회용 컨테이너에서 하나씩 잼: readiness 0.16 · dashboard 1.19 · 지도 1.45 · 검증 1.43 · SGIS 0.07 · 지역 통계 0.07GiB, **구역 입력(`area.warm_inputs`)만 6GiB를 넘어 강제 종료**
- 원인: 구역 입력이 **전국 건축물대장 209만 행(속성 JSON 저장 크기 1.4GB)을 객체로 모두 읽은 뒤** 기본 지역 칸만 골라냄. 단지도 전국 22,176곳을 상세 JSON(88MB)째 읽음. 전국 수집이 끝나면 대장은 더 늘어남
- api가 다시 뜰 때마다 도커 VM(30GiB)을 거의 다 써서 postgres · 워커가 메모리 부족으로 꺼질 위험

## 무엇을 바꿨나
| 항목 | 비포 | 애프터 |
|---|---|---|
| 건축물대장 | 전국 행(속성 JSON 포함)을 다 읽고 파이썬에서 지역 칸만 | 지역 칸으로 SQL에서 거름(2,000칸씩 `IN`), 필요한 세 열만 |
| 단지 | 전국 단지 객체(요약 · 상세 JSON 포함) | 쓰는 열만(번호 · 이름 · 사용승인 · 세대 · 면적 · 좌표 · 칸 · 난방 · 법정동), 지역 판정은 그대로 |

## 숫자 (기준: 실제 DB, 2026-11-21 전국 수집 중)
- 구역 입력 예열: 6GiB 넘어 강제 종료 → **최고 1.47GiB, 45초**
- 결과가 같음: 지역마다 예전 방식으로 센 행 수와 새로 읽은 행 수 — 기본 지역(전주) 대장 70,735 = 70,735 · 단지 364 = 364, 양산 35,979 = 35,979 · 194 = 194, 성남 49,470 = 49,470 · 346 = 346
- 계산 · 화면 바뀜 없음

## 하지 않은 것
- 다른 곳의 전국 단지 표 읽기(`service.py` 등, 2만여 행)는 그대로. 이번 원인은 아니었음
