# 2026-11-21 지역 수집 감시 작업: 사람 없이 끊긴 단계 · 한도 뒤 · 실패 단계를 다시 넣음
- 관련: `backend/app/region_watchdog.py`, `tasks.run_region_watchdog` · `_run_region_locked`(차선을 잡은 지역 기록), `region_prepare._progress_logger`(심장 박동)
- 사용자: "수집이 정상적으로 진행되는지 지속적으로 확인하는 로직과 문제 발생 시 답변 없이도 자동적으로 문제를 해결하고 다시 수집을 이어나가는 로직이 필요"(밤새 전국 207곳 수집, 답할 사람 없음)

## 왜
- 전국 수집은 며칠 걸리고, 그동안 워커 재시작 · 제공기관 일시 오류 · 하루 한도가 생김
- 지금까지: 한도 뒤 이어 받기(`resume_overdue_regions`)는 **지역 화면을 열 때만** 돌았고, 워커가 단계 도중 죽으면 그 단계는 'RUNNING'으로 남아 사람이 다시 넣어야 했고, 일시 오류로 FAILED가 된 단계도 사람이 다시 넣었음

## 무엇을 바꿨나
| 항목 | 비포 | 애프터 |
|---|---|---|
| 감시 | 없음 | 워커 안 작업 `region_watchdog`가 10분마다 스스로 돎(워커가 뜰 때 시작, 한 줄만 돌도록 Redis 키). 결과는 `data/ops/watchdog.json` |
| 한도 뒤 이어 받기 | 지역 화면을 열 때만 | 감시 작업이 10분마다 |
| 끊긴 단계 | 사람이 다시 넣음 | 'RUNNING'인데 그 지역이 차선을 잡고 있지 않음, 또는 'QUEUED'인데 차례가 왔고(앞 차선 끝) 기다리는 작업이 없음 → 15분 동안 지역에 바뀐 것이 없으면 다시 넣음. 정리 단계만 남은 경우도 |
| 실패 단계 | 사람이 다시 넣음 | FAILED는 20분 뒤 다시, 단계마다 최대 2번(`auto_retries`). BLOCKED(키 · 인증 문제)는 다시 넣지 않고 보고만 |
| 차선을 잡은 지역 | 알 수 없음(잠금 값은 토큰) | 잠금과 함께 `carbon:lane-holder:<차선>` = 지역 코드(10분, 실행 중 갱신, 끝나면 지움) |
| 진행 기록 | 진행 문구만 바뀌고 시각은 그대로 | 진행 문구를 쓸 때 `progress_at`과 지역 `updated_at`도 갱신(살아 있는지 판단) |
- 잘못 두 번 넣어도 해가 없음: 차선은 한 번에 한 지역, 끝난 단계는 건너뜀
- 끄기: 워커 환경 `REGION_WATCHDOG=0`
