# 2026-11-23 팀 변화 모델 구역 예측을 잠깐 기억 (U3 S4)
- 관련: `backend/app/team_model.py`(`predict_area`), 시험 `backend/tests/test_team_model.py`(새 시험 1개)
- 근거: U3 설계(`project/working/methods/u3-plan-bundle-design-2026-11-23.md`) 3.5 · 7절 S4, [지역 보고서 변화 예측 절](2026-11-23-u3-report-change-section.md)(#88)의 "남은 것: 시간"
- 사용자: 밤 작업 계획 U3, "시작(화면 Draft 포함)". 모델 응답을 다루므로 Draft

## 왜
같은 계획을 화면이 예측하고(구역 예측) 보고서가 다시 예측하면 팀 변화 모델을 두 번 기다림(행정동 하나 13~29초). 보고서 만들기에 변화 모델 · 로컬 AI가 겹치면 앞단 대기 240초에 가까워짐.

## 먼저 확인한 것: 같은 입력 → 같은 답
- 지금 서비스에 같은 구역 예측(전주 2칸, 주거 30,000 m²)을 두 번 보냄 → 응답 바이트가 같음
- 전주 송천1동(칸 19개 중 17개 사용)을 묶음 ③과 보고서가 따로 부른 두 번도 같은 값(+6,145.2 tCO2e, 80% 2,106.6 ~ 10,423.5)

## 무엇을 바꿨나
- `predict_area`가 서비스에 보낼 요청(팀 지역 · 칸 · 용도 줄 · 몇 년 뒤)과 서비스의 학습 시각(`/status`의 `ready_at`)을 열쇠로 답을 30분, 최대 32개 기억. 다시 학습하면 열쇠가 바뀌어 옛 답을 쓰지 않음. 학습 시각이 없으면(준비 전 · 옛 서비스) 기억하지 않음
- 기억한 답에는 `cached: true`. 숫자는 그대로. 돌려줄 때 사본을 줘서 받는 쪽이 고쳐도 기억은 그대로
- 오류 응답(404 · 422 · 503 · 504)은 기억하지 않음. 공개 주소 차단 · 사전 점검은 기억보다 먼저

## 확인
- 새 시험: 같은 계획 두 번 → 서비스 한 번 · 같은 값 · `cached`, 다른 계획(몇 년 뒤) → 다시 물음, 학습 시각이 바뀜 → 다시 물음, 학습 시각 없음 → 매번 물음, 받은 사본을 고쳐도 기억 그대로. DB 없는 전체 568 통과
- 실측(이 가지, 임시 컨테이너, 저장 안 함): 전주 송천1동 묶음 ③ 뒤 보고서 스냅숏 16.4초 → **7.7초**(남은 것은 구역 분석), 값 같음
- 숫자 · 계수 · 기준: 바뀐 것 없음
