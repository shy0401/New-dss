# 2026-11-19 PR마다 시험 돌리기(CI)와 자동 병합 조건

- 범위: GitHub 워크플로 · 백엔드 시험 표시 · Git 작업 문서
- 바뀐 파일: `.github/workflows/tests.yml`(새로), `.github/workflows/auto-merge-collaborator.yml`, `backend/tests/conftest.py`와 시험 6개 파일(표시만), [GIT 작업 방식 8절](../GIT_WORKFLOW.md)

## 왜
- 협업자 PR은 승인 없이 자동 병합되는데, GitHub에서는 시험이 돌지 않았다. 병합 전 확인은 올리는 사람이 로컬에서 돌린 결과뿐이었다
- 변화 모델 PR(#15 · #17)처럼 서비스 · 화면을 함께 바꾸는 변경이 늘었다. 시험이 깨진 채 병합되는 것을 막는다

## 무엇을 바꿨나 (비포 → 애프터)
| 항목 | 비포 | 애프터 |
|---|---|---|
| PR 시험 | 없음(이름 점검만) | `시험` 워크플로: **백엔드 시험**(Python 3.12, `pytest -m "not db and not local_data"`), **화면 시험**(Node 22, `npm ci` → `npm run build` → `npm test`) |
| 자동 병합 조건 | 충돌 · 경로 · 이름 · 삭제량 | 위 조건 + 그 커밋에서 `백엔드 시험` · `화면 시험` · `저장소 파일 점검`이 모두 성공. 돌고 있으면 댓글 없이 기다리고, 실패하면 댓글로 알림 |
| 자동 병합이 도는 때 | PR 열림 · 커밋 추가 · 초안 해제 | 위 + 시험 · 이름 점검이 끝날 때(`workflow_run`, main의 파일이 쓰임) |
| 백엔드 시험 표시 | 없음 | DB가 필요한 시험 21개에 `db`, PC의 `data/` 자료가 필요한 시험 1개에 `local_data`. PC(Compose)에서는 전처럼 모두 돎 |

## 숫자 (깨끗한 사본, DB · data/ 없이, 이 PC)
- 백엔드: 표시 전 470개 중 448개 통과 · 22개 실패(DB 연결 21, `data/raw/research` 자료 1) · 2개 건너뜀 → 표시 뒤 CI 명령: **448개 통과 · 22개 뺌 · 2개 건너뜀, 9초**(건너뜀: 병합 시험용 PostgreSQL 없음, git 사본 아님. GitHub에서는 git 사본이라 1개 더 돎)
- 화면: 54개 파일 212개 통과, `npm run build` 통과(묶음 크기 경고만)

## 확인
- 자동 병합의 시험 확인 부분을 가짜 결과 5가지로 돌려 봄: 모두 성공 → 병합, 실패 · 취소 → 보류(댓글), 결과 없음 · 도는 중 → 기다림
- 워크플로 YAML 읽기와 병합 스크립트 `bash -n` 문법 검사 통과
- GitHub(PR #20 첫 실행): `백엔드 시험` · `화면 시험` · `저장소 파일 점검` 모두 성공, `시험` 워크플로 약 1분. 자동 병합은 `.github/` 변경이라 예상대로 보류 댓글. 시험 결과를 기다리는 동작(`workflow_run`)은 main에 들어간 뒤 다음 PR에서 처음 확인됨

## 결정
- DB까지 쓰는 시험은 CI에 PostGIS를 띄워도 적재된 실제 공간 자료(`data/`, 올리지 않는 자료)가 없어 통과할 수 없다 → CI에서는 빼고, PC의 컨테이너 시험은 그대로 둔다
- 이 PR은 `.github/`를 바꾸므로 자동 병합 규칙상 저장소 관리자가 직접 확인하고 병합한다

## 하지 않은 것
- CI에 DB를 띄워 통합 시험 돌리기(위 이유)
- 화면 묶음 크기 줄이기(경고만, 이번 범위 밖)
