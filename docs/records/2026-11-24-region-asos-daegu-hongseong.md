# 2026-11-24 지역 기상: 대구는 ASOS 143, 홍성은 ASOS 177로 (대체 자료 → 같은 시 관측)
- 관련: `backend/app/reference_tables.py`(`NORMALS_TO_ASOS`), `backend/app/region_prepare.py`(`ASOS_STATIONS`에 홍성), 시험 `tests/test_reference_tables.py`, [기준 문서](../DATA_STANDARD.md) 2절 · 판 1.57
- 사용자: "대구 · 홍성 기상" — 같은 시에 ASOS가 있는데 대체 자료(ERA5-Land 재분석)를 쓰던 지역을 관측으로

## 왜
- 지역 기상 규칙(2절, 11-16 · 11-21)은 "같은 시 · 군의 ASOS 완전월, 없으면 ERA5-Land(FALLBACK)"다. 11-23 U2-c 기상 준비에서 대체 자료 지역 23곳을 살피다 두 곳이 규칙과 어긋남을 찾음
  - **대구**: 기후 가이드 표(기상청 평년값 1991~2020 지점 연결)가 대구를 지점 860(신암)으로 이음. 860은 평년값 번호라 ASOS 일자료 API가 0행을 줌(11-21 시험) → 번호 300 이상이라 빠지고 ERA5-Land로 남음. 대구의 ASOS는 143(API 응답 지점명 '대구')
  - **홍성**: 홍성 ASOS 177(응답 지점명 '홍성')이 군 안에 있으나, 평년값이 없어 가이드 표가 서산 129(다른 시)로 이음 → 다른 도시라 쓰지 않고 ERA5-Land로 남음
- 11-23 U2-c에서 기상이 대체 자료인 READY 23곳 중 나머지 17곳은 같은 시에 ASOS가 없음(지점 목록 확인). 고창(52790)은 ASOS 172가 이미 연결돼 120개월이 관측, 빠진 달 12개월만 대체

## 무엇을 바꿨나
- `asos_station()`: 평년값 지점 번호를 ASOS 번호로 바꾸는 표 `NORMALS_TO_ASOS = {"860": ("143", "대구")}`를 먼저 적용한 뒤 ASOS(번호 300 미만)만 고름 → 대구 9개 구 · 군 모두 143
- `ASOS_STATIONS`(손정리)에 `"44800": ("177", "홍성")`
- 규칙은 그대로: 같은 도시만, 그달 모든 날이 있는 달만, 응답 지점명이 기대 이름과 같을 때만 씀
- DB 적용: 기상 단계의 ASOS 덮어쓰기(`_asos_overlay`)만 이 가지 코드로 10곳에 한 번 돌림(ERA5-Land · 일사량은 다시 받지 않음, api · worker 컨테이너는 그대로). 도구 `project/tools/experiments/asos_overlay_2026-11-24.py`(PC), 전후 표 `data/derived/asos_overlay_2026-11-24/`(Git 밖)

## 남은 것
- `standard.recompute_degree_days`(코드 기준 판 `VERSION`이 바뀔 때 서비스 시작에서 돎)는 지역 기상 도일을 ERA5 원본으로 다시 계산해, ASOS로 바꾼 달도 ERA5 값으로 덮고 출처 표시는 'KMA ASOS'로 남김. 이번 변경은 `VERSION`을 올리지 않아 일어나지 않음. 다음에 판을 올리기 전에 고쳐야 함
- 군위군은 2023년 대구 편입으로 '광역시 지점' 규칙에 따라 143을 씀(설계 지역 구분은 중부2로 대구 남부와 다름). 군 안 AWS를 쓸지는 규칙을 바꿀 일이라 그대로 둠
- 다른 PC · 팀원 DB는 이 가지가 합쳐진 뒤 대구 · 홍성 기상 단계를 다시 돌리거나, 이 DB로 만든 묶음을 받으면 같아짐
