# 2026-11-23 지역 화면: 지역을 바꾸면 분석 요청 1건이 422로 실패하고 새 지역 첫 분석이 돌지 않던 것
- 관련: `frontend/src/pages/AreaPage.tsx`, 시험 `frontend/src/pages/AreaPage.test.tsx`
- 근거: 사용자 활용 단계 점검(2026-11-23) "지역을 바꾸는 순간 분석 요청 1건 422, 까닭 미확인", 밤 작업 계획의 남는 시간 항목

## 왜 (재현)
지금 서비스(이 PC, 포트 5173)에서 지역 시뮬레이션 화면을 성남(41130)으로 연 뒤 시 · 군 · 구를 과천(41290)으로 바꿈. 브라우저 네트워크 기록:
- `GET /api/areas/options?region=41290` 200, `POST /api/areas/analyze` **422 `{"detail":"행정동을 찾을 수 없습니다"}`**, 그 뒤 분석 요청 없음 → 화면에 오류만 남음

까닭: 지역을 바꾼 렌더에서 "지역 초기화" 효과(행정동 코드 비우기 · 첫 분석 다시 허용)와 "첫 분석" 효과가 같이 돎. 첫 분석 효과는 아직 **앞 지역의 선택지와 행정동 코드(분당구 구미1동)**를 보고 새 지역(41290)으로 분석을 보냄 → 422. 그 사이 첫 분석 표시가 켜져서, 새 지역 선택지가 도착해도 첫 분석을 다시 하지 않음.

## 무엇을 바꿨나
- `optionsReady`(ref): 선택지가 도착하면 참, 지역을 바꾸면 거짓. 첫 분석은 참일 때만. 화면 · 숫자 변화 없음(요청 순서만)
- 사례 링크로 다른 지역을 열 때도 같은 길(링크 지역으로 바꾼 뒤 그 지역 선택지를 기다림)

## 확인
- 새 시험: 41130에서 41290으로 바꾸면 41290 분석 요청은 과천 행정동 코드 하나뿐. 고침을 잠시 빼면 이 시험이 실패함(41290 요청이 분당 코드 `31021510` 하나뿐 = 재현과 같음)
- 화면 시험 221 · `tsc -b` 통과
- 미리보기(포트 5420, 이 가지 화면 + 지금 API): 성남 → 과천 바꿈에서 `options?region=41290` 200 → `analyze` 200, 422 없음, 과천시 갈현동으로 첫 분석
- 숫자 · 계수 · 기준: 바뀐 것 없음
