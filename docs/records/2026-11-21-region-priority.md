# 2026-11-21 전국 수집: 지역 순위대로 받기
- 관련: `backend/reference/region_priority.csv`, `backend/app/region_priority.py`, `tasks._run_region_locked`, `cli prepare-national`. 계획(저장소 밖, PC): `project/working/methods/region-priority-plan-2026-11-21.md`
- 사용자: "수집 범위는 지금처럼 진행하되 … 핵심 지역에 대한 수집을 우선", "우선순위 기준 그대로 진행하고 순위대로 받는 기능 만들어"

## 왜
- 남은 전국(207개 수집 지역, 2025년)을 다 받는 데 며칠이 걸림. 중간에 끊어야 할 때 핵심 지역이 다 갖춰져 있어야 함
- 범위(사이트 · 단계 · 기간)는 그대로, **지역 순서만** 정함
- 지금 구조의 문제: 차선(기본 · K-apt · VWorld · 건축HUB)마다 한 번에 한 지역만 돌고, 잠금을 못 잡은 작업은 30초 뒤 다시 물어 먼저 묻는 쪽이 들어감 → 여러 지역을 넣으면 넣은 순서가 지켜지지 않음

## 무엇을 바꿨나
| 항목 | 비포 | 애프터 |
|---|---|---|
| 순위 표 | 없음 | `region_priority.csv` 207행(순위 · 단계 · 단지 수 · 지역 구분 · 냉방도일 비 · 지역난방 비중 · 까닭) |
| 차선 잠금 | 30초마다 먼저 묻는 작업이 잡음 | 기다리는 지역을 차선마다 Redis 순위 목록에 올리고 **가장 높은 순위만** 잠금을 잡음. 120초 넘게 묻지 않은 항목(워커 재시작으로 사라진 작업)은 목록에서 지워 막히지 않음. 정리 단계(짧음)는 순서를 건너뜀 |
| 전국 실행 | 지역마다 화면 · API로 넣음 | `python -m app.cli prepare-national --until <순위>`(순위대로 넣음, READY · 진행 중은 건너뜀, `--dry-run`으로 미리 보기, `--start`로 이어서) |
| 멈춤 | 없음 | `prepare-national --cancel`: 기본 단계가 아직 대기 중이고 도는 단계가 없는 지역만 멈춤(단계는 PENDING, 그 작업은 실행하지 않고 끝남). 이미 시작한 지역은 끝까지 받아 다 갖춘 상태로 남음 |
