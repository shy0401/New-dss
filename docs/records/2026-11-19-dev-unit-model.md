# 2026-11-19 변화 모델을 개발 단위로 평가하고 서비스 · 화면에 반영

- 관련: PR #15(`model/dev-unit-service`), `deploy/team-model/server.py` · `region_drop.py` · `dev_bands.csv`, `backend/app/team_model.py`, `frontend/src/components/TeamModelPanel.tsx`, [공통 데이터 기준](../DATA_STANDARD.md) 1.19(5.8 · 5.11), [팀 데이터셋](../TEAM_DATASET.md) 7.3절
- 숫자의 공통 기준(따로 적지 않으면): **개발 단위**(맞닿은 개발 칸 묶음, "지금까지 지어진 만큼"), **범위 안 용도**(주거 · 복합 · 상업), **실제 변화 1,000 tCO2e 이상**, 12개 시드 평균. "교차검증"은 42개 지역을 지역 통째로 빼고 학습한 예측, "시험"은 학습에 없던 10개 지역. 오차 = |예측 − 실제| ÷ |실제|의 중앙값

## 왜
- 개발은 대부분 여러 칸이다. 2014 → 2024년 개발 591개 가운데 늘어난 연면적의 66%가 10칸 이상 개발에서 나왔다
- 그런데 모델의 성능은 칸 하나의 변화로만 쟀고, 화면도 칸 하나씩만 예측했다. 쓰임(개발 계획 하나의 배출 변화)에 맞는 성능 숫자가 없었다
- 같은 점검에서 쓰임과 맞지 않는 가정이 더 나왔다: 모델 입력에 연도가 있어 미래 예측에 2024년 자료 특성이 실림, 2024년 결손 표시가 지역 통째로 붙음, 예측 범위 · 성능 표가 옛 모델 기준

## 하지 않은 것 · 보류한 것
- 개발 합계를 바로 예측하는 모델, 합계 보정: 시드 두 묶음 모두에서 나빠 기각
- 되살린 2024년 칸을 개발 사례(가중)로도 쓰기: 대상지(부산 명지) 예측이 크게 나빠져 보류
- 입력 · 기상 · 학습기 설정 변형을 더 시험하기: 칸 단위에서 시드 흔들림 안이었음
- 계량 자료(K-apt · 건축HUB)를 학습 정답이나 입력으로 합치기: 자료 범위가 평가 사례와 거의 겹치지 않음

## 남은 일 · 한계
- 교차검증은 요구 수준에 조금 못 미친다(오차 0.309 대 0.30, ±50% 안 70% 대 75%). 시험 지역은 충족한다
- 계획으로 넣으면 칸 하나씩 본 큰 사례의 예측 합이 실제의 0.854배다(관측 입력은 0.975, 시험 지역 99개). 개발로 더하면 계획 경로는 관측 입력과 거의 같다(학습 합본 교차검증, 개발 220개: 상세 계획 오차 0.303 · 0.324 대 관측 입력 0.305 · 0.311, 합계 비 0.95 대 0.99, 시드 두 묶음). 아래 "계획 입력 변환 점검" 참고
- 화면은 아직 칸 하나만 예측한다 → 여러 칸 개발 입력(7-B2). 개발 합계를 칸에 같게 나누는 규칙을 쓴다(아래)
- 평가는 "지금까지 지어진 만큼"이라 막 지어진 몫이 큰 개발은 정답이 덜 찬다(예측 합 1.11배)
- 결손 표시가 많은 지역(세종 · 부산 강서 · 수원 권선)은 평가 개발에 적게 들어간다
- 기타 비주거(교육 · 의료) 개발을 범위에 넣을지, 원주 2024년 전기 계수, 2025년 자료는 결정 · 확인 대기

## 계획 입력 변환 점검 (7-C, 2026-11-19, 서비스 바뀜 없음)
- 왜: 계획(신축 · 철거 연면적)으로 넣으면 큰 사례 예측 합이 관측 입력보다 작았다(0.854 대 0.975)
- 원인: 계획 변환이 새 건물 건축면적을 동당 연면적 ÷ 가정 층수(주거 20층 · 비주거 5층)로 넣어 190 · 206 m²가 된다. 학습 자료 새 개발지의 개발 뒤 값은 주거 399 m² · 8.5층, 비주거 871 m² · 3.8층이다. 입력 묶음을 하나씩 바꿔 넣으면 평균 건축면적이 차이의 75%를 설명한다
- 시험한 것(규칙은 결과 보기 전 정함): 가정 층수 · 동당 연면적을 학습 자료 값으로 바꾼 판

| 시험 지역 큰 사례 99개 | 오차 중앙값 | ±50% 안 | 예측 합 ÷ 실제 합 |
|---|---|---|---|
| 관측 입력 | 0.302 | 73.7% | 0.975 |
| 계획(지금 서비스) | 0.302 | 73.7% | 0.854 |
| 계획(고친 판) | 0.307 | 74.7% | 0.868 |

- 결정: 고친 판은 **채택하지 않음**. 관측 입력과의 합 차이를 11%만 줄였다(기준: 절반 이상). 차이의 96%가 8개 사례에 몰렸고, 그중 3개는 관측 입력 예측 자체가 실제보다 훨씬 컸다
- 칸 배분(시험 지역 여러 칸 개발 31개 중 1,000 t 이상 24개, 참고 수준): 개발 합계를 칸에 **같게 나눠도** 실제 배분과 거의 같다(오차 0.221 대 0.226, 합계 비 0.979 대 0.950, 기준: 오차 +0.03 · 합계 비 차이 0.05 안) → 여러 칸 개발 입력(7-B2)에서 같게 나눔을 쓴다
- 고친 판을 개발 단위로도 다시 봤다(학습 합본 지역 5겹 교차검증, 겹마다 학습 지역만으로 형태 계산, 개발 220개). 상세 계획 오차 지금 판 0.303 · 0.324, 고친 판 0.306 · 0.315로 기준(두 시드 묶음 모두 0.02 이상 좋아짐)에 못 미쳐 **채택하지 않음**
- 바로잡음: 처음 시험은 결손 칸을 되살려 늘린 개발 표를 잘못 써서 고친 판이 여러 칸 개발 오차를 크게 줄이는 것처럼 보였다(0.196 → 0.123). 서비스 규칙은 되살린 칸을 평가 사례로 쓰지 않으므로 정식 표로 다시 냈고, 위 숫자는 모두 정식 표 결과다
